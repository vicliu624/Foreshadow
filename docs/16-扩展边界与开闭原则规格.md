# 扩展边界与开闭原则规格

[English](16-extension-boundaries.md) · 简体中文

本规格约束整个工程的演进方式。开闭原则要求稳定消费者通过协议使用可替换提供者；添加同一变化轴上的实现时，不修改消费者的行为分支。分目录、函数指针或名为插件的类本身不能证明符合。

## 边界和验收

| 变化轴 | 扩展所有者 | 稳定消费者 | 新增实现的验收 |
|---|---|---|---|
| 接收机及设备特性 | `plugins/receivers/` 与 C ABI | 接收会话、CLI、接收设置页 | 独立构建第三个插件，安装后发现、参数、规则、推荐、采集和分析生效，主体哈希不变 |
| 语言 | 提供者自己的语言资源 | 文本解析器和通用控件 | 只增加语言文件，新语言及逐级回退生效，主体和插件哈希不变 |
| I/Q 编码 | `backend/iq` 编解码接口 | 检测、频谱、研究视图、录制与回放 | 新编码通过同一归一化/满量程契约进入各处理路径，消费者不增加格式分支 |
| 检测器与检测说明 | `adapters/modulation` 提供者及组装注册 | 会话调度、选择菜单、配置评估、结果展示 | 新描述与测试检测器进入选择、评估及调度，界面不增加算法 ID 分支 |
| 快照观察生命周期 | `SnapshotExtension` v2 与注册组装 | `SnapshotAnalysis`、实时 I/Q 订阅 | 独立提供者声明周期或能量触发、窗口与间隔；仅分派匹配策略的提供者，过载不阻塞采集并按实际窗口字节计量 |
| 研究工具及其参数 | `plugins/desktop/research` 提供者或外部工具包 | 分析面板、菜单和后台任务宿主 | 工具的渲染、参数与校验随提供者进入，面板不导入自带工具实现 |
| 实时研究工具生命周期 | `LiveResearchProvider` v3 与 `live_registry.cpp` 组装，v1/v2 兼容 | `LiveTools`、采集订阅者及工作区 | 独立提供者申请接收租约、接收任意起始样本的 I/Q、添加事件/录制操作及多个面板；自动进入 View，完整保留未知事件字段；按工具到主面板索引诊断，不把额外面板当作新消费者；宿主不解析其参数或诊断载荷 |
| 接收机使用权与广播任务 | `ReceptionDemand`／`ReceiverSession`，见规格 21 | 监听管线、实时研究宿主 | 独立接收机及研究提供者验证共享、整套需求冲突、实际回读、独立释放和有界输入，无具体设备或调制 ID 分支 |
| 研究输入文件容器 | `SignalSourceProvider` v1，`backend/iq/signal_source.cpp` 组装 | 分段窗口、后台分析与来源选择 | 提供者声明后缀、资源及读取；验证存储样本到源时钟的显式映射，原始编码与存储编码分开；独立文件容器接入同一窗口消费者，界面与算法无格式 ID 分支 |
| 参考模型及参数 | `ReferenceModelProvider` v3（v1/v2 调用语义兼容），`plugins/research/models/registry.cpp` 组装，见规格 23 | 通用比较内核、参数编辑器、后台任务与模型视图 | 独立提供者带参数描述、整套校验和纯参考函数进入相同拟合/对齐路径；保留自身资源及未知方法字段；消费者不增加模型 ID 分支，不把残差当作调制识别或 EVM |
| 信号恢复与证据 | `RecoveryProvider` v1/v2（v2 复数测量见规格 25），`plugins/research/recovery/registry.cpp` 组装，见规格 24 | 通用结果验证、依赖追溯及后续后台/证据视图 | 独立数字及测量提供者进入同一协议；保留未知事件/方法字段、采样依赖、候选/截断/校验状态；新增结果能力须升级协议，不能把非数字结果或未知字节显示为有效 Hex |
| 事件类型和特征 | 事件生产者及其描述 | 结果表、证据视图和事件存储 | 未知但合规的模块 ID 能显示名称、特征与原始证据，不能被硬编码清单吞掉 |
| 输出/载荷类型 | 有版本的研究结果协议 | 结果宿主 | 已有类型的新提供者不改宿主；全新结果能力通过协议升级明确实现 |

## 责任要求

- 设备规则、检测语义和工具选项不属于通用界面。消费者可以解释通用类型、生命周期、能力声明和结构化错误，不可以识别具体实现来修正其规则。
- 推荐值不是合法值全集，当前主机算力不是设备能力上限。硬件校验、分析适配、运行负载分开表示。
- 配置区分请求、预计和实际回读。未知能力不得编造；缺少驱动事实时由提供者说明启动确认范围。
- 校准和 ADC 过载事实由接收机提供者维护，通过版本化启动回读和接收状态传递，见规格 21。启动观测不能外推为所选窗口持续无过载；参数校正值、数字削顶及软件丢弃也不构成硬件校准或 ADC 观测。旧提供者未声明时保留未知，新增动态或区间遥测必须升级协议。
- 命名占位符和本地化资源由文本协议处理。业务代码传递 key 与变量，不传递中英文并排的句子。
- 数据解码拒绝未知格式、残缺样本和非法值，不能使用兜底分支将未知编码解释成另一个编码。
- 新实现的名称、参数、评估说明、偏好别名和事件呈现信息应与实现一起定义，不能在多个消费者里维护平行清单。

## 允许修改的位置

新增实现可以修改其提供者代码、资源、构建包及明确的组装注册位置。静态内置模块的组装更新不等于稳定消费者可以增加实现分支；运行时插件还需满足不重新构建主体的要求。历史兼容别名是冻结的数据迁移范围。

检测扩展在当前快照输入契约内注册算法、选择和描述；新处理生命周期需要显式协议设计。研究工具通过 `ResearchProvider` 提供渲染与参数控件，外部工具可在清单中声明参数、依赖和语言目录，由共享控件渲染，使用独立 JSON 设置文件传递。资源安装器根据声明复制完整资源，不按工具 ID 选择文件。

桌面语言由 `resources/desktop/languages` 中的语言包元数据发现，包含语言标签、原生名称、别名、QM 路径及可选 Qt 基础翻译。插件的字典与桌面的 QM 分开分发，共用通用语言回退规则；新增语言文件不应修改语言白名单或菜单代码。

新事件应提供 `display_label` 和结构化 `features`，或至少提供 `modulation` / `modulation_id`。旧录制的证据级别读取分支作为冻结的兼容范围保留；架构检查禁止继续增加这张消费方映射。

算法内部按波形、采样边界或协议状态分支属于该算法的领域行为。新的主体能力，例如多设备相干接收、全新结果载荷或协议生命周期，不属于已有型号/提供者扩展，应明确设计与版本化；不承诺所有未来功能都无需修改主体。

## 可执行约束

文件系统原生路径与文本协议分别处理。路径进入 JSON、Qt 文本或 CLI 等 UTF-8 边界时统一使用 `path_to_utf8`／`path_from_utf8`，原生环境变量通过 `environment_utf8` 读取，不能依赖 Windows 当前代码页；POSIX 原生系统调用仍可使用其原生路径字节。发布包验收必须在包含中文及非 BMP 字符的实际安装目录下启动应用、发现模块并安装独立工具箱，而不能仅在 ASCII 构建目录内检查。

依赖检查限制稳定模块导入具体实现；架构契约检查限制实现 ID 路由、分散的 I/Q 解码和嵌入式多语言文字表；资源检查核对 key 与占位符；行为契约通过独立提供者和资源增量验证扩展。原有调制、录制、界面、本地化和实体接收机回归必须继续通过。

修改本规格不能替代实现验收。发现未覆盖的变化轴时，先明确所有者和协议，再整改消费者与验证；不得通过放宽检查来保留新增耦合。

## 实时处理与资源边界

采集、录制、检测和显示的连续性分别计量。分析过载不能阻塞采集或将软件分析丢弃标成驱动丢样。驱动未提供硬件样本计数器时，只报告已知的读取、超时、拒绝和连续性标志，不保证硬件绝无丢样。

分析缓冲以实际载荷字节及采样时钟约束，不能用 USB 回调个数代替内存和时间预算；短读不应缩小承诺的缓冲时间。录制缓冲满时明确停止，不能静默覆盖原始样本。扩大缓冲不能代替持续吞吐验证。

检测提供者维护多信号结果及证据条件；宿主完整接收其合规事件，不能以单个结果槽吞掉同一子频段内的其他信号。子频段并行使用相互独立的算法状态，任务结束后按频段顺序合并结果；线程数按主机资源推荐，显式设置保留，不将小屏设备的线程预算当成算法或接收机能力上限。

状态发布只复制已完成的快照，不等待另一检测器的整段 DSP。界面同时说明 CPU 占整机比例和等效核心数，分别显示各分析阶段的丢样和队列预算。实时验收同时包含短读、持续输入、所有选定检测器并行、多个同时存在的信号，以及无证据时避免误报的负例；短录音零丢样不能代替长时间硬件验收。

实时研究提供者拥有输入字节预算、连续性和输出恢复策略。音频输出欠载与 I/Q 拒绝、PCM 延迟丢弃分别统计，不能把可恢复的输出欠载当成解调器失败。I/Q 数据视图及订阅契约属于 `backend/iq/stream.hpp`，不能让研究实现反向依赖会话编排；旧订阅头作为源代码兼容入口保留。
