# 分发许可材料协议

[English](distribution-compliance.md) · 简体中文

这是 Foreshadow 发布组装使用的第 1 版许可材料协议，独立于
[规格 17](17-受控工具箱与在线更新规格.md)的签名工具箱清单／安装协议。
安装器不解释许可证 ID，不裁定版权争议，也不会创造上游未授予的许可。
交付清单是项目自定义 JSON，不宣称通过 SPDX／CycloneDX 认证；上游提供的
原始 SPDX 文件作为证据保留。
组包工具要求 Python 3.12+，本次使用 3.13 验收；原生应用不依赖 Python 运行时。

## 所有者与组装位置

接收机所有者维护 `plugins/receivers/<provider>/licensing.json`，外部研究提供者
维护自己的 licensing.json，应用根属于 `resources/licensing/application.json`。
schema 1 声明包含 packages（包 ID 到组件根的映射）和 application（随主体交付时
需要的根）。CMake 将资源安装到 `share/signalscope/compliance/providers/`。

CMake 在其父目录生成 build-facts.json，记录分发平台、Qt、OpenSSL 和应用版本；
它是构建事实，不是提供者声明。新提供者增加自己的资源、注册与经过评审的组件
证据，不向收集器、界面、会话或安装器增加提供者 ID 分支。

## 评审配置与材料

`resources/licensing/profiles/*.json` 固定支持的平台／构建事实、各包根、运行库归属
规则与组件定义。组件包含版本、许可表达式／替代项、上游来源、依赖、明确的 issues
及是否需要源码。可选 display_notice 是提供者维护的醒目声明；独立接收机的索引
不会虚构 Qt 或编解码依赖。

制品条目以 SHA-256 固定真实源码归档、原始声明或构建元数据；仓库材料固定路径、
角色与哈希。配置使用 LF 文本，使跨平台字节稳定。自研源码来自冻结 Git 提交，
SOURCE-DELIVERY.json 标明生产子集：省略研究历史、旧补丁、外部测试夹具及独立
评审的固件，保留全部生产代码、提供者资源、导入源码与构建／安装脚本。

collect_materials.py 校验缓存和仓库哈希、复制真实文件并提取原始声明；每份声明
保留来源归档与成员路径。提取文件使用哈希前缀的短文件名，既保留原始字节与来源，
又不在 Windows 安装时重建过深的上游目录。缺少源码、构建或声明角色会失败。

compliance.py 核实构建事实与提供者根，把材料装入新安装树，记录原生二进制指纹，
生成 `share/foreshadow/compliance/inventory.json` 与 index.html。PE／ELF／Mach-O
文件必须有唯一的已评审所有者；未知可执行文件或附加材料后变化的二进制会失败。
精确文件名归属只证明该构建配置，不会自动授权新增 Qt 模块。

## 独立包与发布检查

package_release.py 为每个主体、接收机和研究归档计算依赖闭包，嵌入材料并生成
verification.json。路径保持包内相对路径；交付真实源码，不用源码主页链接代替。
通用安装器将这些文件与包一起保留。

正常组包拒绝未决 issues；私下评审可明确使用 --review-only，保留原因并将报告标为
review-only，但不能绕过源码、声明、哈希、版本或归属检查。独立 RTL-SDR 和
power-report 包可以材料完整，同时主体／SDRplay 闭包仍有未决授权条件。

正式目录签名前，sign_catalog.py 重新打开实际归档，对照仓库评审过的配置核对
材料哈希、源码身份、包闭包、运行库规则和组件身份／未决条件，确认固定的上游
制品与仓库材料确实存在。删除生成清单里的问题不会改变配置中的结论。保留的旧目录
条目也须重新提供归档以便验收，不默许历史未验收包继续进入新目录；继续提供旧版本
期间应保留相应的历史平台评审配置。

Windows 通用安装事务在最终目录改名时，仅对原生访问／共享／锁冲突进行最多五秒的
有界重试；其他错误立即失败，持续占用仍会失败且不提交注册表。原生测试以独立包类型
持有真实目录句柄，在中文／非 BMP 路径覆盖短暂占用和持续占用；没有新增按提供者 ID
分支，也不关闭系统防护。

正式工作流要求经过评审的材料包 HTTPS URL 和 SHA-256，再核实源码提交与实际构建
事实；滚动依赖和未支持的平台不会自动放行。日常契约／回归继续用自托管 Runner，
发布私钥保留在仓库外。

## 验证及边界

Python 契约套件使用独立虚构的提供者和包，验证深目录声明，并覆盖缺少源码、材料
篡改、二进制变化、未知归属、版本不符、路径越界、源码提交不符与删除未决条件。
原生验收检查中文／非 BMP 路径中的实际归档、独立安装及主体／模块启动；源码重建
和库替换证据分别报告。

机械材料检查不是法律意见。SDRplay API 授权、编解码专利、外部媒体权利和固件范围
需要独立证据；功能测试、动态库形式或根目录 GPL 文本都不能免除上游条款。另见
[许可范围](../LICENSING.zh-CN.md)、[第三方声明](../THIRD_PARTY_NOTICES.zh-CN.md)
和[源码／替换说明](../SOURCE_AND_REPLACEMENT.zh-CN.md)。

## 0.2.12 独立基础包与服务客户端

基础包排除可选 SDRplay 客户端，客户端仅包含网络适配器和核心库，不包含独立安装的
服务、厂商运行时。提供者声明 `bundle_with_application:false`，组装器排除该提供者声明的
代码、资源、专属运行库并保留共享文件。各包按实际闭包检查；可选包存在未决条件时仍拒绝该包，
但不阻断无关基础包。独立提供者契约同时验证这两种结果。此前 2026-11-13 直连完整包的
评审限制保留为历史证据，不作为新网络客户端的依赖声明。
