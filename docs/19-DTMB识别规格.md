# DTMB 识别

[English](19-dtmb-detection.md) · 简体中文

## 目标与证据

依据现行 [GB 20600-2006](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=41F48525779777A75F0898B87E9BD24E) 的帧结构识别 DTMB。帧头三种模式 PN420、PN595、PN945 均须验证标准序列及重复帧时序；适用于单载波和多载波帧体。识别结果提供帧头模式、相关证据、已检查帧数、估计中心频率和源样本位置。不能用频率、能量平台、普通 OFDM 循环前缀代替 DTMB 证据。

本阶段的能力为波形及帧结构识别。没有完成系统信息解码、信道均衡、LDPC/BCH、传输流恢复前，不声明星座、码率、节目名称、音视频播放或成功解析电视内容。

## 所有者与扩展边界

算法、参数、输入覆盖要求、评估说明、事件特征和语言资源由 DTMB 检测提供者维护。组装仅位于调制模块的注册目录及 CMake 组装。主窗口、菜单、设置评估与通用事件表不得按 DTMB ID 路由，也不得添加并排多语言表。

持续电视信号不应依赖功率突增才被观察。快照扩展协议 v2 显式新增由提供者声明的观察策略，支持既有能量触发和周期观察；宿主按照策略收集有界、连续的样本窗口，并仅调度声明匹配策略的检测器，保持旧检测模块的触发行为。策略必须包含窗口时长、观察间隔及最低输入速率，超载时报告分析窗口跳过，不能阻塞采集或称为硬件丢样。独立测试提供者应验证该协议，不能只为 DTMB 增加专用调度分支。

不同观察策略各自拥有一个有界任务槽，较慢策略不得占住另一策略的处理机会。通用状态分别报告各策略的触发、完成、忙时跳过、待处理及处理中载荷字节，并保留整体汇总；不以新增算法 ID 创建调度分支。

完整的中国 8 MHz 频道是可靠识别的输入覆盖目标。采样带宽、接收机实际滤波器、搜索范围和边缘截断分别说明；带宽不足的接收配置不得显示为保证识别。处理经样本编解码接口取得的归一化 I/Q，保留原始采样时钟及任意非零起始样本坐标。

## 验收

1. 使用标准附录 D/E 的独立 PN 位向量和图 12 的寄存器定义验证方向、极性、周期与截短。合成正例覆盖三种模式、帧头相位变化、两种帧体、非整数采样比、频偏、定时偏移、噪声、多径及不同 I/Q 编码。
2. 负例覆盖噪声、单音、FM、常规 CP-OFDM、其他 PN、只出现一次的合法帧头、错误帧间隔及不连续样本，避免将已知 PN 的孤立相关峰称为稳定 DTMB。
3. 验证持续输入无需能量跳变即可产出结果，主流水线不等待 DTMB DSP；输入及状态内存有界，负载及跳过可见。回放、CLI 扫描、菜单、接收配置评估、事件显示和语言回退通过通用协议接入。
4. 按公开频道栅格在 31.42 的 RSP 接收环境扫描，保留原始短样本和来源统计，用结构判定选择实机正例。天线、环境或缺少当地信号导致无法取得正例时，单独记录外部条件，不能把标准合成样本通过称为当地实收成功。
5. 执行架构、契约、已有回归及实际归档的 Unicode 路径验证。测试通过后按既有发布和签名协议分发，部署核验实际二进制、模块和配置。

## 频率参考

扫描候选优先使用 UHF 13–24 频道（中心 474–562 MHz，间隔 8 MHz）和 25–36 频道（中心 610–698 MHz，间隔 8 MHz），补充 VHF 6–12 频道。频道栅格见[广电公开频率表](https://www.nrta.gov.cn/module/download/downfile.jsp?classid=0&filename=6d7f314d26524eb896d2473fbcd65f58.pdf)。这些是扫描候选，并不表示当地每个频道都有 DTMB 发射。

根据[工信部无〔2020〕50 号](https://wap.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2020/art_e5389a57ece640b4bd1b69dd74cff8a7.html)，702–798 MHz 已重新规划用于移动通信，不能将该频段的移动通信 OFDM 直接视为 DTMB。标准文本、公开栅格、当地实际占用和接收测量各自承担其事实来源。
