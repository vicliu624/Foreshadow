# 插件、提供者与 Foreshadow 宿主

[English](plugins.md) · 简体中文

**Foreshadow 是围绕插件构建的工作台。大部分信号领域功能由提供者实现，桌面把这些能力组织为共享研究流程。** 接收机、检测、显示、波形实验室、参考模型、恢复、FM 和电视都有所属模块与明确协议。

本文解释当前实现。工程要求仍以[规格 16](16-扩展边界与开闭原则规格.md)、[分发规格 17](17-受控工具箱与在线更新规格.md)及[工作区规格 18](18-桌面工作区与模块界面规格.md)为准。

## 宿主负责什么

宿主提供各模块协作所需的公共基础设施：

- 样本、流和来源协议，编解码服务、时钟、源坐标与不连续表示。
- 接收会话与租约、整套需求冲突、有界输入交付和生命周期。
- 录制、重放、事件存储、保留策略及通用来源/证据持久化。
- 可停靠工作区、自动 View 菜单、通用工具承载、参数控件和证据视图。
- 目录信任、通用安装事务、包类型适配与应用激活/回滚。

共享 DSP 内核实现滤波、重采样、参考拟合、证据校验等公共操作。提供者通过协议交付领域算法和前提条件。具体设备规则、调制参数和恢复算法不能因为结果显示在主窗口中，就转由主窗口维护。

## 功能来自哪些插件

内置 [ADS-B 模块](adsb.zh-CN.md) 增加探测、恢复和实时地图面板。
其集成与验收仍在进行，模块说明区分已验证证据与待完成的运行及硬件检查。

内置 [WSPR 模块](wspr.zh-CN.md) 通过独立长时接收和录音动作提供 WSPR-2 解析及台站结果面板，
不把 110 秒消息送入亚秒级快照检测协议。

| 提供者类别 | 职责与实例 | 当前接入形式 |
|---|---|---|
| 接收机插件 | RTL-SDR/AIO2、SDRplay；发现、能力、参数、联动、推荐、校验、应用顺序、回读、驱动运行库与翻译 | 独立构建的原生模块，通过接收机 C ABI 在运行时发现 |
| 检测模块 | LoRa 结构、窄带调制特征、FM 导频、CSS/PSK/OFDM/DTMB 候选；拥有输入要求、描述、证据及资源 | 注册的内置实现，随应用组装 |
| 显示提供者 | 频谱、瀑布、I/Q 预览及相应渲染行为 | 内置桌面显示组装 |
| 实时研究提供者 | 波形实验室、FM 接收/音频、DTMB 电视；拥有面板、操作、状态、后台作业、参数和接收需求 | 内置 `LiveResearchProvider`，由通用工作区承载 |
| 参考模型提供者 | 常量/单音、AM、FM、FSK、Chirp、LoRa、PSK、OFDM 参考生成，以及参数、联动和整套校验 | 注册研究提供者，宿主通用比较观测和生成参考 |
| 恢复提供者 | FSK 成帧、LoRa PHY、明确成对编码帧族、训练式 PSK/OFDM；同步、信道/均衡、符号/字节/帧、复数测量及校验证据 | 注册恢复提供者，公共后台/界面/导出消费证据协议 |
| 外部研究工具 | 原生功率报告及兼容快照工具；声明输入、参数、输出、资源和运行载荷 | 独立可执行文件/清单协议，可独立分发为研究工具箱 |
| 媒体编解码提供者 | FFmpeg 解码器与 DRA 核心；轨道接受、能力、解码器创建和诊断 | 隔离媒体辅助进程内注册的原生实现 |
| 语言资源 | 各提供者文案、参数、说明、命名占位符与逐 key 回退 | 资源随所属提供者分发；桌面语言元数据有自己的发现协议 |

目录名不等于边界。例如检测提供者目前位于 `src/adapters/modulation/`，模型/恢复位于 `plugins/research/`，二者都是扩展协议的所有者。实际路径见[源码地图](../src/README.zh-CN.md)。

## 插件、提供者与工具箱的区别

**插件**描述产品的模块化能力；**提供者**是某个扩展契约的实现；**工具箱**是安装、分发和版本管理单位。一个模块可以属于插件架构，同时随主体应用包交付。

| 形式 | 目前能否独立安装 | 增加实现是否需要重建宿主 | 更新与生效 |
|---|---|---|---|
| 接收机原生 ABI 模块 | 可以，接收机工具箱 | 现有 ABI 能表达时不需要 | 进程启动时发现，原生变更重启生效 |
| 外部快照研究程序 | 可以，兼容的研究工具箱 | 现有快照/输出协议范围内不需要 | 通过受管资源/清单发现，遵守运行作业和安装冲突规则 |
| 内置检测/显示/实时研究/模型/恢复/媒体提供者 | 随应用交付 | 当前组装需要应用构建 | 随应用更新，保留适用的模块选择入口 |
| 新语言资源 | 通过所属资源协议加入 | 受支持资源扩展无需修改算法或消费者 | 依相应协议发现和回退，并验证实际安装 |

所以，工具箱中心的一项“内置分析”可以承载多个提供者，并不表示算法在中央窗口中实现；同样，注册提供者也不自动意味着可下载的动态库。原生接收机和外部快照工具的生命周期、能力与分发协议也各不相同。

## 用户从哪里接触插件

1. **Plugins → Toolbox Center**：官方可信目录、已安装包、兼容更新、离线包及待激活状态；区分已安装、已加载和待生效版本。
2. **Module settings**：当前应用开放的模块选择；内置能力标为随应用交付并随主体更新。
3. **Receiver settings**：通用渲染选中接收机的整套参数；提供者判断待应用联动、推荐、阻断冲突、应用与回读。
4. **Detection**：检测器描述与选择；通用事件视图显示提供者标签、字段、特征，保留协议合规的未知 ID。
5. **View**：已注册显示和研究面板；实时提供者可增加面板、操作和声明的布局，缩放保留用户安排。
6. **Model comparison / Evidence and recovery**：选择研究提供者，其参数/校验驱动界面，公共图表、表格和导出展示类型化结果。

打开/关闭/隐藏面板、启停检测器、安装包和释放接收租约是不同操作。隐藏的实时工具可以继续工作；冻结研究观测不必然停止其他接收使用者，应查看工具的实际状态与停止操作。

## 以新增恢复方法为例

现有恢复协议能表达的实现应增加：

1. 稳定标识、方法/协议版本及资源命名空间。
2. 参数描述及针对整套待应用配置的校验、联动和限额。
3. 算法与类型化证据：观测、源支撑、阶段、符号/比特/字节/帧、校验，以及可选复数测量。
4. 英文及其他语言资源、缺失回退。
5. 声明的恢复注册点及相应构建/资源增量。
6. 通过既有后台、视图、持久化和导出的独立数值、反例及资源验收。

宿主不添加 `if method == new_id` 行为分支。旧协议无法表达的新能力，需要明确升级协议及消费者。静态注册是允许的组装点，不代表已经支持独立二进制安装。

其他变化轴遵循相同原则：设备事实归接收机，检测语义归检测模块，模型/恢复规则归研究提供者，样本解释归编解码模块；普通算法条件不必全部变成插件。

## 扩展证明与运行边界

测试包含宿主不变时独立构建/接入的接收机，独立检测、实时研究、模型、恢复、媒体实现，纯语言资源增量及回退，通用参数联动、未知事件、复数证据、持久化和真实工具箱事务。目标/头文件依赖与架构检查补充行为证据。

插件边界不能单独证明物理性能。设备兼容、模块加载、调制结构、字节恢复、必要校验、EVM 和设备身份是不同结论；提供者声明能力范围，平台、包和硬件验收分别记录。

当前是官方受控分发渠道，没有任意源市场或第三方自助上传。外部快照工具不会自动获得原生实时面板或接收租约，新生命周期需要显式协议设计。

## 独立接收机服务（0.2.12）

基础应用与可选 SDRplay 服务客户端工具箱分别交付，厂商 API/驱动仅由独立安装的接收机服务加载。
提供者所有的连接描述和请求协议 2 在设备枚举前传递地址，界面、会话和 CLI 保持通用。
固定 BSL SoapyRemote 客户端依赖 SoapySDR 0.8.1，支持离线覆盖
`FETCHCONTENT_SOURCE_DIR_SOAPYREMOTE`。只有声明为随主体捆绑的提供者进入基础归档；
原始 CMake 安装目录是组装暂存树，不是已验收基础归档。SDRconnect 评估、安装、协议、连续性和
许可边界见[接收机服务](receiver-services.zh-CN.md)。
