# 波形实验室与可追溯分析实施规格

[English](22-waveform-laboratory.md) · 简体中文

## 目标与依据

本规格落实 2026-11-11 用户确认的工作区原型和 P0→P3 实施顺序。交付对象是实际 Qt 桌面功能、共享计算、提供者协议、资源及验收证据，原型或静态研究图片不能替代交付。遵守规格 16、17、18 及当前规格 21；保留已有录制、检测、广播会话、工作区布局与用户偏好。

研究者可以从录制、实时捕获或事件取得一段明确的 I/Q 数据，沿同一时间坐标观察、测量、提出模型假设、对照误差并复查检测证据。未知调制同样允许观察、测量与模型假设；不能以检测 ID 白名单阻止研究。

## 数据与数值约束

实时研究工作区新增 `LiveResearchProvider` v3：保留 v1/v2 字段顺序与生命周期，末尾增加额外面板描述及 `recordingActions(ResearchRecordingContext)`；录制上下文使用原生路径、文件相对的可选样本区间和未经 ID 筛选的事件字段。事件操作可以声明显示本提供者的已注册面板。宿主按工具到主面板的显式索引保存状态与诊断，不把额外面板当作另一个实时消费者。多面板采用通用 View、放置与保存恢复机制，面板关闭不停止提供者。外部快照 IPC 未因此获得原生多面板或实时输入能力。独立多面板及录制输入提供者验证兼容与失败隔离。

1. 样本序号使用整数；绘图时间以整数差值除以实际采样率换算。文件偏移、源流样本序号、片段相对时间分别表达。没有绝对时间基准时不编造 UTC。
2. 编码、字节数、归一化及满量程使用统一编解码接口。窗口保留原生文件路径，字符串边界使用 UTF-8 路径接口。
3. 允许多个连续段，缺口不补为零、不连线、不跨段求相位差或展开相位。未知长度的不连续同样形成边界。原始 I/Q 和幅度可用性与相位/频率估计有效性分别表示。
4. 幅度过低时相位与频率无效；第一样本没有相邻相位差。包裹相位、分段展开相位、原始与平滑频率及其参数分别标注。平滑不跨无效段。
5. 计算先使用完整分辨率样本，显示再按像素聚合。聚合保留极值、不连续与无效区，不能改变光标读数或测量值。
6. 相邻相位差提供的是离散复基带频率估计；明确参考点、混叠范围、低幅度及多信号限制。原始 I/Q 平面不称为完成定时/载波同步的星座。
   通过数值/幅度检查只表示该相位差可计算，不能声明载波存在或信噪比充足。噪声同样具有相位差和可能的周期图峰；后续模型及解码的证据门槛由各提供者维护，不能用“可计算频率点数”替代。
7. 每项结果保留源引用、输入区间、方法/版本、单位、参数、有效范围和处理历史。理论对照说明手动参数、估计参数、对齐及允许的自由度；残差不自动证明调制或故障来源。EVM 只在明确参考与同步条件下提供。

## 工作区行为

接收机与会话控制保持可访问；中央为捕获总览及联动轨迹，右侧为测量/模型/证据，事件与录制继续使用通用工作区。监听与研究布局为用户显式选择的布局预设，普通缩放不覆盖布局。面板支持 View 恢复、停靠/浮动、标签组合和跨启动持久恢复。小屏及 1.25 倍缩放需要实际验证。

模型与证据页在实施后提供真实结果，不保留“P2/P3”占位标签。所有用户可见文字来自所属语言资源。持续采集、预览、冻结、录制、后台计算及已停止状态明确区分。

## 433 MHz 真实调查补充

用户在“分析31.42上的433MHz数据”聊天明确要求将临时研究暴露的功能缺陷纳入本任务，2026-11-11 已承接。研究参考位于被 Git 忽略的 `recordings/433-survey-20261111/`，其中 `analysis.json` 记录原始 I/Q SHA-256；原始 SigMF 与脚本只作为验收素材，不将临时脚本作为生产接口。

- P0 保留整数源坐标、输入身份、连续性及原始/派生数据身份。派生采样与原始采样的有理比例和滤波时延需显式进入协议，不能把派生序号冒充原始整数样本。
- P1 加入全带总览到目标信道的时间/频率选区，频移、低通、polyphase 重采样等处理有参数和版本；复用或适配现有通用 `Channelizer`，正确表达其延迟与边界有效区。目标信道的 STFT、PSD、幅度与窗口平均功率使用共享时间映射。功率为明确归一化基准的 dBFS，不冒充未校准的 dBm。
- P2 使用目标信道的可验证样本进行模型对照；P3 从保存事件回到该处理链和原始录制，原始/处理后均可复查，并保存重开配置。
- 回放案例包括：433.012 MHz 附近 SF11/BW500k 的扫频结构；434.7246 MHz 被 OOK/ASK 交替标记但呈持续窄载波/周期频率摆动的反例；428.8068 MHz 位于实际接收滤波边缘的重复扫频。具体数值属于调查候选，应由后续回放验收确认；重复标签不能当作多设备/多报文，显式头候选不等于载荷解码或设备用途确认。
- 真实录制不能替代独立真值、反例、编码扩展和独立提供者验收，不将这些原始录制上传到公共仓库。

同一调查聊天随后补充了“从信号恢复实际携带信息，查看十六进制”的要求，已纳入 P3 的实际交付，不能将 I/Q 文件字节当成空口载荷：

1. 使用版本化的通用解码结果描述符号、比特、字节、帧及它们与源采样/处理链的映射。宿主提供 Hex/ASCII、帧界限、长度、时间、源范围、点击回到波形及保存导出；已知协议可以附字段，未知协议保留原始候选数据。
2. 同步、参数假设、判决、比特映射、去交织/纠错/去白化/帧组装由所属提供者负责。稳定宿主不得按调制/工具 ID 增加规则。
3. 分开表达候选、同步失败、校验通过/失败/不适用/未携带/未知、纠错错误、截断和可能加密。只有满足所属协议验证条件的内容才能标为有效帧；模型拟合或头校验通过均不代替载荷正确。
4. 首个端到端闭环需要明确调制、参数及帧协议条件，用独立已知字节的信号真值检验完整链路；不承诺任意未知私有协议都能通用恢复。其他提供者使用同一描述接入。
5. LoRa PHY 与 LoRaWAN 分开。调查中的三份 SF11/BW500k 录制存在一致显式头候选（50 字节、CR4/5、未携带 payload CRC）。早期未补偿时钟漂移时出现 12–19 个 parity 错误/99 个码字；后续有限参数搜索得到 payload parity 全部通过的字节候选，但其中两份仍有头块剩余数据字节歧义。以调查最新的 `payload-refined-unverified.json` 等证据及参数为准，不将中间步骤固化为最终结论。缺少 payload CRC 与应用协议验证时，这些仍是候选；不作为正确载荷真值，不猜测设备用途。两种状态用于验证处理配置、FEC、CRC、歧义与协议语义必须分别展示。
6. 信息不一定是数字字节。解调提供者需要区分数字候选/已验证帧、模拟音频或测量、不支持等结果能力。只有数字链到达相应阶段才显示 Hex，不将模拟载波强制判决为字节。约 67 Hz 摆动仅是待验证特征；弱载波或低信噪比使瞬时频率不可信时，应阻止下游解释，不据此推测设备或业务用途。

调查随后增加了 `protocol-profile.json`、`protocol-verified.json`、`protocol-decoded.json`：累计 15 帧的字节候选通过经验帧族内的 CRC16 关系消歧，48 字节成对编码可还原 24 字节，内层补和也通过，含未参与推导的 4 个后续帧。上述第 5 点记录的歧义属于此前研究阶段，不能据此否定后续独立校验；实现与验收应核对最新文件。经验 CRC 模型在固定长度下的 init/xorout 不唯一，不注册为已知命名协议。载荷内部 CRC 与 LoRa PHY 的 payload CRC 标志分别表达；“字节及校验关系已得到验证”和“业务字段/设备用途仍未知”分别展示。该经验帧族只进入所属研究提供者/可保存的研究配置，不能硬编码到通用宿主。

最新 `followup-report.json` / `followup-frames.csv` 扩展为 36 个严格零 parity 错误内容、3 个单列弱候选及 1 个未恢复结构事件。弱候选包括 1 个 parity 错误但载荷不变、2 个无效 01/10 对被唯一 CRC16+内层补和约束修复；39 行内容不能统一标为 39 个严格帧。调查报告将封装记为 E32/CDEBYTE 兼容候选，硬件厂商及业务含义仍未确认。应用字段的新假设将旧 `app[10:14]` LE32 拆为 `app[10]` 单字节序号和 `app[11:14]` LE24 分钟计数，`app[14:16]` 为 BE16 秒；历元、用途与未知字段单位尚未确认。六字节标识只作不透明值，不能当作 MAC/OUI。后续 P3 必须核对最新资产并自行复现，这些调查结果不能提前算作本任务解码验收。

用户补充现场条件：采到这些信号期间没有主动操作发射设备。此案属于被动观察，没有受控触发对照；不能据此归因邻居或物业，也不能排除无人操作的自有设备。最新调查资产中的 `user_observation_context` 应随经验帧族证据保留，不能从字节校验关系推导设备来源或业务含义。

研究场景也会改变采集条件。433 MHz、10 MS/s 和当前增益不是固定产品限制。P0-C 的研究闭环包含：选择目标→研究提供者声明完整信号与保护带、采样/通带及增益/AGC需求→接收机插件维护能力、规则和建议→对整套待应用配置及共享使用者求值→通用流程应用与回读→重新捕获。界面显示冲突和影响，不静默重配其他接收使用者。录制与结果保存请求、实际回读、校准和过载状态；数字缩放不修复模拟削顶。依据规格 21 的接收租约协议实现，不把设备或调制 ID 分支写入主窗口。

调查阶段曾针对滤波边缘、目标信道宽度与增益进行受授权的硬件复采。本任务在 2026-11-12 核对调查聊天已结束且无其他接收客户端后，使用隔离程序完成实体被动输入验收；未修改正式桌面设置或现有部署。后续再次使用设备仍须先核对现有使用者，不能从本次空闲状态外推设备一直可用。

## 资源与持久化

### 文件来源与冻结窗口

`SignalSourceProvider` v1 的组装位置为 `backend/iq/signal_source.cpp`。提供者维护后缀、资源域/key、原生路径、存储样本数量、源流参数和读取函数；通用消费者根据注册描述选择来源，不按容器 ID 分支。存储编码与原始输入编码分开：规范化 CF32 文件不被当成原始 CI16/CU8 再次归一化。每个源映射给出连续的存储索引、整数源时钟起点、数量及未知长度的不连续标记。完成的读取逐段核对其声明映射、样本数量及容量，I/O 分块不成为额外源边界。

冻结容器使用 `org.amc.signal-window` 版本 1，目录中为 `capture.amc-window.json` 和按编解码接口编码的 `samples.cf32`。元数据保存源 UUID、原始编码、实际流参数、原始时钟及显示原点、全部连续段、处理/接收上下文；所有位置和数量使用十进制字符串。没有绝对到达时间时 `absolute_arrival_utc` 为 null，`saved_utc` 只是保存时间。分段数据不伪装为连续 SigMF。数据目录必须独占新建，先完成样本，再通过临时清单重命名发布；失败只清理本次创建的固定文件，保留未知文件和既有目录。

研究配置版本 1 的已有引用继续读取；版本 2 明确增加以分析文件目录为基准的相对引用。通过 `path_to_utf8(..., PathTextFormat::generic)` 保存可移植的 UTF-8 分隔形式，原生路径与边界转换仍统一使用路径接口。配置与旁边捕获目录一起移动后仍可重开；任意缺失/改变的原始引用仍须给出错误，不能宣称永久可用。

### 目标信道与有理时钟

`backend/dsp/signal_processing` 拥有原始观测到目标信道的数值转换。`ProcessedSignal` v1 保留不可变原始窗口、输出采样率和精确源时钟映射，位置表达为整数加既约分数；不经 double 往返大序号。`AnalysisTrace` v2 的索引属于其声明的分析时钟，通用轨迹与 I/Q 平面通过分析接口读取数量、速率及范围；原始窗的已有消费者仍走整数源时钟。

`ProcessedSignal` v2 增加文件描述与精确文件样本范围的来源形式，和 RAM 窗口二选一；`AnalysisTrace` v3 明确支持这种没有常驻原始样本的来源。处理结果不能把小预览当成整段原始观测，也不能凭空构造一个已载入的原始窗。时间偏移从原始文件的时钟原点计算；通用轨迹、平面与窗口研究使用同一声明的分析时钟和来源能力。文件缺失后缓存的已完成处理结果仍可查看，后续重读/复现必须另行核对来源可用性及身份。

`AnalysisTrace` v4 增加可选的紧凑子集映射；空映射指针继续使用 v1–v3 的完整父轴。映射使用同一分析时钟、整数起点和紧凑值下标，只能指向父输入中实际存在的点，不能跨越已知缺口或抹去未知不连续。通用轨迹按各自映射绘制，成对平面要求相同映射；未计算点保持空白。共享映射的容量只计一次。窗口频率统计按特征自身映射读取，不能以父轴下标读取一个较短的特征数组。该能力允许参考结果只分配所选实际点，不为小选区复制整个大预览。

分块文件提取通过既有来源读取协议，按中心块及滤波支撑两侧的重叠读取，所有块固定相同的有理输出网格和混频原点。只向预先规划并分配的输出位置写入恰好一次，缺失或重复位置、未声明的处理历史变化、预算或取消都不得发布半成品。原始与输出编码仍通过编解码接口统一；不识别文件容器 ID。读取、系数/临时输出、映射、输入数量、含重叠的实际读量和运算分别限额。当前默认中心块 8,192 点、读载荷 1 MiB、工作区 4 MiB、映射载荷 8 MiB；单次任务的输入/实际读取分别最多 100M/256M 点，并继续受输出及运算上限约束。长文件可以只处理指定范围，不声称整个长录制可无限量一次计算。

后台文件信道输入使用独立的 `org.amc.normalized-recorded-range` v1 摘要：声明的源流、原始时间原点、选中文件范围、分段坐标/不连续与处理历史组成版本化头部，随后按文件顺序以 CF32 编解码语义增量计入全部实际规范化样本。元数据 SHA-256 单独保留；摘要不包含文件路径，中心块不重叠计数、支撑重叠不重复哈希。它不是仅覆盖当前原始预览的旧窗口摘要，也不冒充整份文件哈希。读回仍须与已冻结原始预览的重叠样本逐位一致，并验证已有完整输入摘要，防止把旧预览与变更后的长范围输入混成一个结果。文件工作区与映射预留计入后台联合预算。

研究配置 v5 / 信道配置 v2 增加独立的录制输入范围及完整输入身份，原始预览范围仍单独保存。信道范围可以大于预览，但都须通过提供者整套评估与预算。处理选区超出预览时保留真实选区，不能把它静默夹到预览边缘，也不能将“尚未载入”写成源缺样；元数据已知的文件索引仍可显示。用户可从处理 B 载入最多 16,384 点的原始邻域，执行已应用的处理链并核对完整输入身份，保留处理选区/分数光标，不应用草稿。改变输出采样率后按精确来源时间重映射视区与处理光标；原始与输出时钟上的邻近观测点明确区分，不伪造插值原始样本。配置和录制整体移动后，新实例仍须可重开，且不依赖旧数据路径。

离线信道提取对整套频偏、完整通带、每侧过渡带及输出采样率校验，执行精确频移和居中 Blackman-sinc 多相 FIR。只输出具有完整观测支撑的点，已知或未知长度缺口均截断支撑，连续 I/O 小块不截断。记录因果等效群时延、时间戳补偿和边缘丢弃策略。按输出载荷、懒加载系数相位缓存及运算次数分别限额，不为互质采样率分配无限相位表。

既有 `Channelizer` 的实时 FFT 分箱/固定响应及零边界行为保持；研究要求的精确频偏、自选过渡带及完整观测支撑用独立的离线方法表达，不能假装原接口已有这些能力。该方法不承担无限量长期流式转换保证；有界文件按需读取采用前述 ProcessedSignal v2 协议与验收。

研究提供者拥有目标信道参数页与“原始观测/目标信道”轨迹。时间选区经精确映射双向联动；处理光标显示分数源位置，原始光标仅定位其前一个原始采样点，不冒充插值后的原始观测。配置 v3 保存原始来源及摘要、处理方法版本、已应用参数、独立视图及光标，重新打开时从原始数据重算。冻结容器 v1 仍只储存原始整数时钟样本，不能用于隐式输出分数时钟数据。

后台作业联合预算默认为 128 MiB，包含原始窗口、原始/处理后轨迹、处理样本和系数载荷；旧 UI 结果替换期间可与一个新结果共存。不能只分别满足各条流水线预算却忽略共同存活的结果；后续时频矩阵、模型及证据结果也须纳入。

窗口研究与原始/信道分析共用同一个后台队列，只有一个运行任务和一个最新待处理请求。选区计算复用已完成的不可变轨迹，不能再开独立流水线长期持有多代大窗口。作业先从联合预算中预留矩阵和计算工作区；当前默认分别为 16 MiB 和 4 MiB，再为原始/处理后样本及轨迹分配剩余额度。热图的最大值聚合缓存与工作区另限 4 MiB，通用曲线最多 65,536 点并按像素聚合；这些是载荷限额，不是整个 Qt 进程 RSS 的无条件上限。

研究配置 v4 增加窗口研究的方法版本、实际输入时钟、已应用窗函数/FFT/hop/单位/统计参数、精确计算范围与色标视图。旧版本继续读取，但不能以旧版本声称存在新的处理能力。选区变动使用 100 ms 最新范围合并，待计算期间不保存一份伪装已同步的配置；打开新来源时丢弃旧刷新请求。重开先复现保存的独立范围，之后用户的新选区才触发联动。时频框选只修改目标信道草稿和原始时间范围，不隐式执行 DSP 或接收机配置。

窗口研究内核的谱值保持线性，显示时再以功率基准 1 转换 dB。双边复数 PSD 的单位为归一化功率/Hz，按频率间隔积分；每频点功率采用可直接求和的独立归一化。周期窗的能量、相干增益、等效噪声带宽、帧支撑及平均范围随方法保存。没有校准证据时只能显示 dBFS 或 dBFS/Hz，不能标成 dBm。自相关不去直流，不跨不连续边界，按实际配对数归一化；相位/频率无效点不进入频率统计或直方图。长文件与桌面视图通过前述按需读取、通用后台和配置协议接入，验证范围见最新实施报告。

后台保存线程持有不可变样本和已应用参数/视图快照，保存后实际回读并核对规范化窗口摘要，配置由 `QSaveFile` 原子提交。保存期间暂停跟随新窗口但继续采集，不并发启动新的分析计算；人工后续冻结最多保留一个待显示窗口。取消不在 UI 线程 join；若捕获副本已经验证、后续配置失败或取消，分别报告副本位置与配置状态。不能把配置成功和完整样本成功混为一个无条件成功标志。

输入队列按实际字节计量；实时回调只做有界复制/入队，数学与绘图不在采集回调中执行。研究保留窗口的正常过期、输入拒绝、已知采样缺口、采集/录制/检测的丢弃分别计量。只发布已完成快照，单个消费者异常隔离。

`backend/iq/signal_capture` 拥有通用有界原始输入到分段窗口的捕获流程，不依赖会话或 Qt。入队使用 try-lock、实际 vector capacity、块大小和块数预算；工作线程单独解析。保留缓存同时限制规范化载荷、源时钟跨度和片段数，极短读取不能无限增长元数据。冻结请求是已接收入队序列的 FIFO 边界，后台复制不可变窗口；请求之后的输入继续处理，不能混进该冻结范围。停止及换源清理待处理输入并分开计量，旧源结果不能发布到新代次。该流程需要与提供者的接收租约、处理预算、冻结持久化和桌面工作流共同验收，单独通过内核测试不代表 P0-C 完成。

冻结数据、分析轨迹、缓存与时频矩阵都受明确预算约束，峰值包含同时存活的输入和结果。长文件按范围读取，不为绘制概览一次载入整份录制。保存配置明确源身份与数据可获得性；含缺口的捕获不得以无缺口的普通录制伪装导出。
