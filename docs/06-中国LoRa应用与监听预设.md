# 中国 LoRa 应用与监听预设

[English](06-china-lora-presets.md) · 简体中文

## 1. 调研结论与边界

调研日期：2026-11-03。中国民用计量与物联网中存在 LoRa 应用，因此环境观察具有现实依据，但无法由公开产业资料判断用户附近是否部署、何时上报、采用何种私有参数或能否接收到。

工信部《工业互联网和物联网无线电频率使用指南（2021年版）》列出民用计量仪表的 470–510 MHz 范围。这为优先观察该频段提供依据，不代表该范围只存在 LoRa，也不是任意设备发射许可。[工信部指南](https://wap.miit.gov.cn/cms_files/filemanager/1226211233/attach/20216/6f2d2602200448009b156a1e7863d8c2.pdf)

Semtech 与 LoRa Alliance 资料记录了杭州水表等厂商采用 LoRa 的智能计量方案；水表厂商的通信模块产品也列有 CN470 选项。它们证明产品和应用存在，不证明当前所在地的覆盖情况、市场占比或具体信道。[Semtech 生态资料](https://www.semtech.com/lora/ecosystem/sensor-features)、[LoRa Alliance 智能计量白皮书](https://lora-alliance.org/wp-content/uploads/2021/01/White-Paper_WHY-UTILITIES-ARE-CHOOSING-SMART-LoRaWAN%C2%AE-CONNECTIVITY.pdf)、[杭州山科通信模块产品](https://www.seckmeter.com/product/nonmagnetic_smart_water_meter/splittype_nonmagnetic_communication_module/95.html)

LoRa 是物理层调制，LoRaWAN 是协议。中国私有抄表设备不一定遵循 LoRaWAN，NB-IoT 等其他制式也可能用于计量，不能将所有智能表视为 LoRa。

## 2. 法规与版本依据

2019 年第 52 号公告附件给出民用计量设备的场景、频率和技术条件，包括 470–510 MHz、占用带宽上限及单次发射时间限制。这些是特定设备类别的条件，不是软件主动发射的授权。本软件仅被动接收和离线重放，用户测试设备应保持其适用配置。[公告正文](https://www.miit.gov.cn/zwgk/zcwj/wjfb/gg/art/2020/art_4f2c890530cc4837b2113cf977e249c4.html)、[官方附件](https://wap.miit.gov.cn/cms_files/filemanager/oldfile/miit/n1146285/n1146352/n3054355/n3057735/n3057748/n8004149/c8006552/part/8006563.pdf)

LoRa Alliance 已发布 RP002-1.0.5；CN470 方案存在版本和不同信道计划，不能将旧版的固定上下行列表作为所有中国 LoRa 的事实。当前官网入口已核对，但其完整新版信道表尚未在本次逐项提取，因此第一版不硬编码“全国统一最优信道”，也不按旧版规则推断上行/下行。[LoRa Alliance 当前规格入口](https://resources.lora-alliance.org/technical-specifications/rp002-1-0-5-lorawan-regional-parameters)

原厂 CN470 模组也列明 470–510 MHz 工作范围，提供额外产品证据。产品支持范围不等于用户现场实际使用范围。[有人物联网 WH-L101 使用资料](https://www.usr.cn/uploads/20250107/WH-L101-LoRaWAN%E4%BD%BF%E7%94%A8%E8%AF%B4%E6%98%8E%E8%B5%84%E6%96%99-V1.0.1-20250107134910.pdf)

## 3. 建议预设

以下为接收研究预设，不是已发现信号的位置或发射建议。频率均指目标信号的中心搜索区间，而非原始采集边界。

| 预设 | 中心搜索范围 | 方式与用途 |
|---|---|---|
| 用户设备验证 | 以用户实际测试频率为中心，默认宽 1 MHz | 固定连续守候；窗口内随机改变发送频点验证未知频率能力 |
| CN470 起步观察 | 470.0–471.0 MHz | 固定连续守候的可解释起点；不是已证明更活跃的窗口 |
| CN470 环境探索 | 470.0–510.0 MHz | 分窗口长驻留探索，记录漏听空档和每窗实际观察时长 |
| 活动窗口守候 | 根据已捕获事件选择宽 1 MHz 的区域 | 后续固定守候，提高稀疏重复突发的捕获机会 |
| 自定义已知频段 | 由设备标签或用户资料指定 | 不默认欧洲 868/美国 915 等预设适用于当地设备 |

固定窗口默认先用 BW125 kHz、SF7–12 搜索；较宽 BW 在实现与负载验证后可选。私有参数未知的环境需记录未搜索的组合，未检出不能当作该窗口无 LoRa。

## 4. 探索窗口与驻留提案

初始中心区间用宽 1 MHz、步进 0.8 MHz 的重叠窗口覆盖 470–510 MHz，最后窗口裁剪到边界；这是软件探索计划，不是 200 kHz 等硬件逐信道扫描。各窗内同时采集和搜索所有中心位置。每窗采集范围仍须加完整目标 BW 和保护带，并满足实测通带能力。

按左端点 470.0 + 0.8i MHz、最后覆盖到 510.0 MHz，可构造 50 个窗口。建议探索驻留可设 30–120 秒，初始 60 秒；该数值只是待测试的观察预算，不代表计量终端的上报周期。50 窗一轮约 50 分钟加切换开销，单个窗口有效观察约占一轮的 1/50，重叠部分另计。

这类探索会错过只发送一次的短突发。即使反复轮询也不保证捕获；周期性信号可能与轮询形成固定相位错开，后续可加入有界驻留抖动并显示实际覆盖。需要尽量完整收集短突发时应固定守候一个窗口。

探索发现候选可在单窗额外预算内保留样本并提示固定守候；明确显示自动延长上限，不能无限驻留。结果按频率、证据和实际观察时长汇总，不能只按原始事件数判断哪个窗口更活跃。没有事件的窗口仍记录有效观察时长。

## 5. 两类现场会话

先用用户设备建立真值闭环：未知中心搜索、强弱变化、结构验证、原始录制、离线复现。再停止主动发射，进行固定窗口长时观察；必要时探索其他窗口并回到活动窗口守候。

记录地点的粗略环境、天线和增益、日期时段、覆盖记录、检测参数、候选和文件。若用户设备与环境事件无法区分，来源保持未知。不得仅凭频段和重复间隔标为“某水表/某协议”，也不把环境未知样本计入已知标签准确率。

当前没有用户现场捕获、频谱调查或本地信道分布证据。具体最优窗口由后续实际观察决定。
