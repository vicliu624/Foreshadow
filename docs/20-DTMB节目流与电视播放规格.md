# DTMB 节目流与电视播放

[English](20-dtmb-television.md) · 简体中文

## 交付闭环

在既有 DTMB 帧结构识别之上，实现持续 I/Q → 同步与系统信息 → 均衡、解交织、LDPC/BCH、解扰 → 有效 MPEG-TS → 节目与音轨选择 → 画面及声音播放。支持实际接收与 I/Q 文件，不以打开外部播放器、只生成空文件或只显示节目名作为电视播放完成。

初始参数以自动发现为默认：PN420／PN595／PN945、系统信息及其调制、编码率和交织方式分别有证据和失败状态。保持输入精度，统一经样本编解码接口取得归一化 I/Q；私有解码管线使用已声明的浮点协议，不绕回 8 位量化。有效纠错与传输校验不能为了得到输出而关闭。对不支持或无法锁定的模式明确说明，不伪称节目解析成功。

采样时钟与符号定时属于接收链路。任意录制起点、分数符号采样相位和合理的源时钟偏差必须有对应捕获及恢复验证，不能只用恰好对齐的一段录音证明接收能力。重采样不能只更改名义采样率而忽略判决采样时刻；发现模式后仍须以实际纠错、节目表和媒体结果确认接收成功。

## 所有者与组装

| 变化轴 | 所有者 | 稳定消费者 |
|---|---|---|
| DTMB 解调、自动模式、参数及恢复 | DTMB 接收适配器 | 通用 I/Q 接口、实时工具宿主 |
| TS 分帧、PAT／PMT／SDT、CRC 与连续性 | 传输流模块 | 电视接收提供者、媒体工作进程 |
| 音视频编解码及其可用能力 | 媒体解码模块及编码提供者 | 电视面板、通用媒体帧协议 |
| 节目、音轨、音量、视频显示和播放状态 | DTMB 电视提供者 | 工作区及事件操作宿主 |
| 第三方源码、数据与许可证 | 固定版本依赖组装 | 构建、打包与通用安装事务 |

`LiveResearchProvider` v2 在保留 v1 组件、I/Q 订阅、事件操作和诊断的基础上，提供独立接收租约，见[独立广播会话与状态栏规格](21-独立广播会话与状态栏规格.md)。主体不按 DTMB ID 路由。节目及解调参数不放进主窗口。模块组装只发生于声明的注册目录和 CMake。媒体工作进程需要带版本的消息与长度边界，不能把新能力伪装成旧的图片／快照文件协议。传输流、媒体和 DTMB 参数各自负责本领域规则，不按接收机厂商或 ID 调整算法。

可复用开源实现固定到具体提交，保留许可证及修改说明。第三方代码的测试也必须确认断言与校验实际启用。不能只信任依赖项目声称的支持列表，须验证进入实际应用的解码链路。

## 交互

从 DTMB 事件可打开电视面板，也可通过 View 显示面板，按当前接收中心启动。提供停止／开始、节目选择、音轨选择、音量、静音、打开 I/Q 文件、导出有效 TS、接收与播放状态。自动配置为默认，深入参数由该提供者拥有、校验和保存。

状态区分无源、输入不适配、缓冲、PN 发现、系统信息锁定、纠错、等待节目表、等待关键帧、播放、恢复及失败。节目表须来自有效 PAT／PMT；名称来自有效 SDT 或明确的无名称回退。节目变化、输入缺口、源切换及停止不能残留为仍在正常播放。加密或没有可用解码器的轨道标注原因，不能显示成功播放。解码器能力包含实际验证的 AVS+ 与 DRA 路径，不能只用 MPEG-2 示例冒充完成中国 DTMB 播放。

## 实时及媒体约束

采集线程只提供有界、非阻塞的 I/Q 副本。解调、节目流和音视频处理均有实际载荷字节预算；原始输入拒绝、各处理阶段跳过、TS 连续性、解码错误、视频迟到和音频欠载分别计量。输入缺口需要清空相关状态并重新同步，不能跨缺口拼接伪造连续节目流。CPU 不足时报告实时率、队列与丢弃，不限制接收机公开能力来掩盖处理不足。

视频显示与音频输出以媒体时间戳同步，处理 PTS 回绕、节目切换和不连续。音频供给不依赖 GUI 定时器；GUI 停顿不能产生无界帧队列。停止和关闭有确定的退出行为；旧会话的异步结果不得复活已停止的工具。原生媒体解码在独立进程中隔离，异常只影响该可选工具，错误与诊断由提供者持久呈现。

媒体辅助进程的输出节流不能在等待未来视频时间戳时阻塞后续音频解码。实时输出须在输入等待时独立推进，按实际编码后消息字节约束音频、视频及控制队列，并将写出中的消息计入预算。结束消息不得越过已解码的媒体；时钟跳变丢弃、生产背压和写出失败分别保留证据。真实连续音频的到达节奏与独立队列契约共同验证，不能仅通过提高播放器缓冲或隐藏欠载计数处理调度错误。

共享构建机器的实际到达节奏使用预先确定的三次观测，记录每次最大间隔、对应时间戳及队列统计，以中位数判断可重复的供给空档；三次观测都必须保持帧数、解码完整性和字节预算。这个测试不把一次墙钟停顿归因为特定算法，也不以反复执行直到某次通过作为验收。平台调度停顿与原生音频输出欠载的证据分别保留。

原始音频到达间隔的中位数门槛保持 120 ms。每次真实媒体观测同时运行独立的 24 ms 定时控制，并记录每个控制等待的实际时长；macOS 控制线程申请与输出线程相同的 QoS。只有三轮都有至少八个控制观测、QoS 申请成功，且三轮控制中位数的中位数达到 48 ms，才认为此主机反复错过至少一个定时周期。在这种环境下原始音频门槛仍超限时，时延资格明确记为平台外部阻断（CTest 跳过码 77），不能写为时延通过；帧数、解码、预算或排空失败始终失败。不能用这个控制证明某一次音频间隔的具体原因，也不能扣除控制时间后声称已经达到原始门槛。发布流水线保存各平台的完整原生测试日志，包括通过及受阻的全部三轮数据；实际平台播放与设备输出验证单独报告。

输出线程按平台声明交互式播放的调度用途；macOS 使用 pthread QoS，申请失败须保留错误码，不伪装成实时保障。输出快照分别保留各通道的截止时间延迟、写出耗时及写出间隔，和读取进程的到达时间观测相互核对。系统调度、管道背压及生产端停顿不能仅凭接收端的一个间隔就确定原因。QoS 不提供硬实时保证，也不能代替实际播放及资源预算验证。

短媒体结束时若定时控制未满八个观测，最多延长两秒以补足相邻控制窗口；仍不足时不能按上述条件记为平台受阻。该延长只收集控制数据，不重新运行媒体，也不改变原始音频间隔、样本数门槛或媒体完整性条件。

同一资格测试在 CTest 与解压后的真实归档检查中使用一致的结论协议。归档检查按单个调用声明可跳过的返回码；没有声明的非零码，以及该调用的其他错误码仍失败。通用检查器不能按测试或实现 ID 猜测错误含义，也不能让一个时延受阻跳过后续解码、界面或依赖检查。

所有可见文字使用提供者资源 key；新增语言与缺失回退须验证。I/Q、TS 和第三方资源的文件路径均遵守原生路径及 UTF-8 边界，真实发布归档须在中文及非 BMP 目录下验证。

编解码提供者的专属错误和说明由该提供者的语言资源构造通用消息，媒体 IPC 保留本地化字段；播放器和电视面板不得为新增编解码器维护错误翻译或实现 ID 清单。广播节目名的字符编码属于传输文本编解码模块，显式编码标记优先，未标记文本使用已声明的接收配置，不按桌面语言或系统代码页猜测。

## 完成验收

1. 独立参考及规范产生的完整波形经过真实接收链路恢复 TS，核对内容、CRC、连续性与纠错结果；覆盖三种 PN 和宣称支持的单／多载波、调制与编码组合。噪声、错误模式、破损输入和无有效输出不能被判为成功。
2. 有视频与音频、含多个节目的测试流经过完整调制／解调后，在实际提供者界面列出节目，切换节目和音轨，呈现视频帧与非零音频，并核对时间戳同步。AVS+、DRA 的实际解码分别提供证据，不以伪造插件代替真实编码器。
3. 实时连续输入、I/Q 文件、背压、缺口恢复、GUI 暂停、重复启停、源切换、断流、无音频设备和媒体进程失败均验证；保持采集与其他检测／研究工具可用。
4. 新增独立提供者或资源的契约验证及原有回归通过。真实包的模块、资源、第三方运行库、许可证与独立工具箱安装在支持的平台验证。
5. 实机尝试接收当地 DTMB；没有可用发射信号或天线条件不足时如实记为实收未验证，不影响标准样本验证的真实性，也不能将它写成电视实收成功。软件交付仍须完成真实画面和声音播放闭环。
6. 在冻结源码上完成正式构建和签名发布，按既有安装及激活协议部署，核验实际运行的二进制及模块。只有所有要求完成并有对应证据，才能报告本目标完成。
