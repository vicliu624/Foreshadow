# 接收机插件协议与扩展

[English](15-receiver-plugin-protocol.md) · 简体中文

接收机通过运行时加载的原生模块接入。主体只依赖接收机协议，不链接 librtlsdr、SoapySDR 或厂商 SDK。RTL-SDR/AIO2 与 SDRplay 是随发行包安装的两个插件；第三个独立模拟插件用于验证扩展，不安装到生产目录。

## 职责边界

| 内容 | 所属模块 |
|---|---|
| 枚举、打开、设备身份、驱动依赖、参数应用顺序和实际回读 | 接收机插件 |
| 参数名称、类型、单位、选项、默认值、可用性及说明 | 接收机插件 |
| 频段空洞、天线限制、直采、增益、IF、ADC 标称位数、设备推荐档位 | 接收机插件 |
| 参数控件、冲突说明、应用状态、设置持久化 | 通用桌面界面 |
| 所选检测器能否处理该输入、分信道方案、完整信号边缘余量 | 主体分析层 |
| 计算积压、分析缺口、录制和设备错误的展示 | 主体工作区 |

主体先向插件索取候选推荐配置，然后用与监听相同的分析预检筛选；不能改频率、关闭用户选择的检测器或用主机算力缩小硬件能力。插件可以提供与静态推荐档位不同的候选。设备特有规则不再通过主体中的接收机 ID 分支实现。

## 发现、安装和依赖

入口为 `signalscope_receiver_plugin_v1`，协议声明在 `include/signalscope/adapters/receivers/plugin_api.h`。模块文件名以 `amc-receiver-` 开头，扩展名为 `.so`、`.dll` 或 `.dylib`。每个平台和架构编译自己的模块；不要求同一个二进制跨系统运行。

默认搜索：

- 构建目录或 Windows：可执行文件旁的 `receiver-plugins/`。
- 多配置构建：可执行文件上一级构建目录中的 `receiver-plugins/`，适用于 `Debug/`、`Release/` 子目录。
- Linux 安装：可执行文件相对的 `../lib/signalscope/receivers/`。
- macOS：`Foreshadow.app/Contents/MacOS/receiver-plugins/`。
- 额外用户目录：存在 `HOME` 时的 `~/.local/lib/signalscope/receivers/`。

`SIGNALSCOPE_RECEIVER_PLUGIN_PATH` 设置后**替换**默认搜索目录，便于第三方安装和完全隔离的测试。Unix 用冒号分隔，Windows 用分号分隔。发现发生在进程启动时；安装或移除模块后重新启动程序。运行中的采集不会卸载插件。

`signalscope receiver-plugins` 返回每个已加载或拒绝模块的路径、ID、ABI 或错误。ABI 不兼容、入口缺失、重复 ID、格式不支持或依赖无法加载时，拒绝该模块并保留其他可用模块。没有接收机插件时，离线命令和录制回放仍可用。

## 二进制接口

ABI 1 使用固定宽度整数、函数指针、上下文指针和借用缓冲区。模块声明 ABI 版本与结构体长度，主体检查后才调用。C++ 字符串、容器、异常和内存所有权不跨越模块边界；可选 C++ SDK 仅用于插件内部。

- `metadata_json`：稳定 ID、显示名称、源标识、输出格式、默认增益、发现排序优先级等。
- `request`：UTF-8 JSON 控制请求，结果通过同步回调返回。
- `stream`：配置请求加二进制 I/Q、启动回读、取消查询和最终结果回调。

控制操作：

| 操作 | 输入 | 输出 |
|---|---|---|
| `devices` | 请求协议 1 为空对象；协议 2 可带 `settings` | 设备列表和可用性 |
| `probe` | 设备索引、可选序列号 | 设备事实、能力、来源 |
| `parameters` | 能力快照、整套待应用配置 | 当前配置下的参数描述 |
| `plan` | 能力快照、整套待应用配置 | 硬件有效性、冲突、有效参数、数据量、ADC/IF 等 |
| `recommend` | 能力快照、用户请求 | 插件给出的有序候选配置列表 |
| `configure` | 完整配置 | 请求值、实际值及确认来源 |

控制返回 0 表示成功；失败返回非零并通过结果回调返回结构化错误。内置 SDK 保留普通配置错误、操作错误与接收流错误的分类。主体侧回调异常先保存，再请求插件清理停止，返回后在主体侧重抛，不让异常越过 C 边界。

## 参数和联动

通用语义字段包括 `sample_rate_hz`、`frequency_hz`、`antenna`、`auto_gain`、`gain_tenths_db`、`input_mode` 和 `if_bandwidth_hz`。厂商参数放在配置的 `settings` 对象内，以稳定 key 存储。频率字段使用 64 位整数 Hz，避免原来的 32 位上限截断 5.8 GHz 等配置。

描述中的 `extension: true` 生成额外控件。支持 `boolean`、`integer`、`number`、`enum`、`string`，以及 `label_key`、`description_key`、`choice_labels`、`unit`、`default`、`choices`、`minimum`、`maximum`、`step`、`visible`、`enabled`、`read_only` 和 `requires_stop`。文本通过资源 key 引用，C++ 中不维护中英文并排的文字表。主体不需要识别厂商 key。

每次编辑都会用完整待应用配置重新查询描述和计划；插件可以动态改变选项、范围或可用性。内置共享 SDK 支持声明式 `enabled_when`，复杂规则可以由插件代码实现。禁用控件不会绕过最终校验。保存的无效值保留并显示冲突，不静默替换成另一个合法值。

冲突包含 `code`、`field`、`scope`、`blocking` 和 `values`。插件在 `values.message_key` 指定消息 key，用命名参数提供动态数据；缺省 key 为 `issue.CODE`。无需向主体增加设备错误码分支。扩展参数使用 `settings.KEY` 定位到对应控件。存在阻断冲突时不能应用。

## 插件语言资源

模块元数据的 `catalogs` 列出相对模块目录的资源目录，按列表顺序叠加。每个目录内用 `en.json`、`zh-CN.json`、`fr.json` 等语言标签命名文件，内容为稳定文本 key 到字符串的映射。内置插件复用 `amc-receiver-common.i18n`，再叠加自己的 `amc-receiver-ID.i18n`，翻译不依赖接收机型号分支。

例如，参数只报告 `label_key: parameter.antenna.label`，对应语言文件各自提供文字；枚举选项使用 `choice_labels` 引用资源。错误模板可使用 `{key}`、`{maximum_hz}` 等命名占位符，变量由计划返回，插件不拼接翻译句子。

主体在加载时读取资源并解析 key，桌面统一按完整语言标签、逐级移除子标签、英语、驱动原始文本或 key 回退。`fr-CA` 可以使用 `fr.json`；缺少某条法语翻译时仍可使用该条英语。增加或修改插件语言只需部署资源并重新启动，不重新编译主体或插件。主体界面本身的 Qt 翻译资源保持独立。

安装插件时一起分发其声明的资源目录。资源缺失、格式错误或目录越出插件包时明确拒绝该插件并保留其他可用插件。SDK 示例测试在二进制安装后额外复制法语资源，确认新语言及回退生效，且主体和插件的 SHA-256 都不变。

RTL 插件拥有调谐器频段档案和基于 USB 板卡身份的 AIO2 HF 直采规则。SDRplay 插件通过 SoapySDR 查询驱动能力和高级设置，维护 RSP 的 ADC/天线规则；会改变 RSPduo 拓扑的模式设置不属于当前单接收流接口。推荐、设置、监听三条路径使用同一套插件硬件校验。

应用时区分用户请求、插件预计和驱动回读。设置失败不会当成成功保存，不能把部分应用过的硬件状态声称为事务回滚成功。

## 样本与连续性

ABI 1 的主体输入格式为交错 `cu8`、小端 `ci16_le` 和归一化的 `cf32_le`。统一编解码接口管理名称、字节数、归一化和满量程；检测、频谱、录制和研究视图不自行分支解释格式。CF32 的满量程分量幅度为 1，非有限样本明确拒绝。其他驱动原生格式需要插件转换或后续协议增加格式支持。I/Q 存储格式、ADC 标称位数、实际有效位数分别表示。

样本缓冲区在同步回调期间有效，单块不超过请求的 `block_bytes`。原始样本索引从零开始，严格连续；主体检查非空、整对齐、块长和连续性。插件报告的能力格式必须与模块流格式一致。取消或主体回调失败时插件必须释放设备并返回。

流发生缺口时，当前协议按明确错误终止，保留结构化统计和部分录制状态。不能伪造连续采样索引继续发送。RTL 没有硬件序列号，软件计数为零不证明硬件没有丢样。I/Q 走二进制回调，不逐样本编码为 JSON。

当前插件在进程内执行，便于高吞吐和借用缓冲区；C 接口与异常边界不等同于隔离厂商驱动的进程崩溃。多通道相干、硬件触发或其他新的主体功能需要协商扩展版本，不能以“新增型号”为由假定主体已具备这些功能。

## 第三个插件如何证明独立扩展

`plugins/receivers/test_receiver` 仅包含 C ABI 头与 JSON 依赖，不链接主体、接收机 SDK或现有驱动，可独立 CMake 构建：

```sh
cmake -S plugins/receivers/test_receiver -B build-example \
  -DAMC_RECEIVER_SDK_INCLUDE=/path/to/installed/include \
  -DAMC_JSON_INCLUDE_DIR=/path/to/nlohmann_json/include
cmake --build build-example
```

构建主体后复制该模块及其语言资源到独立搜索目录，用相同主体执行设备发现、参数描述、联动校验、推荐、实际回读、原始采集和监听分析。测试前后核对主体 SHA-256 不变。此插件有独立的节能/宽带档位、前置放大器和时钟校正；节能模式限制采样率并禁用前置放大，推荐政策刻意不同于能力预设。中英文桌面测试验证自动控件、5.8 GHz、禁止冲突应用、推荐修复及设置回读。

另测试不兼容 ABI、重复 ID、损坏模块和插件移除。生产安装仅带 RTL/AIO2 与 SDRplay 模块，不把模拟设备混入实际设备列表。

第三个独立接收机输出 CF32 I/Q，使用自身编码实现，验证主体的统一编解码、采集、录制和分析通路。它没有链接主体编解码库。共享资源解析器位于 `backend/iq/text_catalog`，与具体接收机无关。
