# 受控工具箱与在线更新

[English](17-toolboxes-and-updates.md) · 简体中文

## 产品边界

AMS 使用官方目录分发应用与工具箱，不提供拖拽连线、任意软件源、账号市场或第三方自助发布。工具箱是安装和版本管理单位，模块是运行单位。平台维护会话、调度、录制和统一结果宿主；工具箱只能通过所属类型的公开协议接入。

现有接收机和外部研究工具作为独立工具箱分发。静态链接的检测、显示和研究模块标记为随应用发布，中心不得声称可独立替换。内置模块原有选择与管理入口保留。

## 责任边界

| 变化轴 | 所有者 | 稳定消费者 | 验收 |
|---|---|---|---|
| 官方目录 | 签名目录协议、发布工具 | 更新服务、中心界面 | 添加新工具箱条目不修改中心或安装器 |
| 包类型 | 类型适配器及注册位置 | 通用安装事务 | 独立测试类型能通过同一事务安装，不增加包 ID 分支 |
| 网络获取 | 传输适配器 | 目录与安装服务 | 本地 HTTP 测试覆盖超时、中断、重定向和校验 |
| 接收机模块 | 接收机工具箱适配器 | 接收机加载器 | 已启用受管版本覆盖同 ID 预装版本；禁用屏蔽该工具箱，卸载受管版恢复预装版本 |
| 研究模块 | 研究工具箱适配器 | 研究宿主 | 安装后资源、参数和运行功能生效，停用与卸载可见 |
| 应用替换 | 平台更新助手 | 更新界面 | 等待父进程退出，切换版本，启动确认失败恢复旧入口 |

消费者不得按某个工具箱、厂商或版本 ID 选择行为。目录、网络、磁盘状态、安装类型和界面分离。文案使用翻译资源。

## 版本与兼容性

应用版本、工具箱版本、协议版本和构建身份独立记录。发布版本遵循语义版本规则，预发布不高于同号正式版本。目录按平台与架构选择构建，Linux 还区分发行版基线。缺少适用构建、主体范围不匹配、未知协议、依赖不满足时展示原因并阻止安装。

同一工具箱 ID 的版本选择由受管安装记录决定，不取决于目录遍历顺序。用户安装、预装和当前进程已加载版本分别表示。动态库的安装、更新、停用、卸载在重启后生效；正在运行的进程不卸载原生模块。

## 官方目录及包

客户端固定官方目录及发布公钥，不提供任意源编辑。目录使用 Ed25519 签名，包含版本、说明、下载大小、SHA-256、展开大小、适用平台、依赖和模块描述。网络传输使用 HTTPS；SHA-256 用于内容一致性，签名用于来源认证。

包包含完整资源及 manifest，不执行安装脚本。安装前验证签名目录、包哈希、身份和版本、文件路径、展开大小、重复路径及组件结构。拒绝目录越界、非法链接和损坏归档。离线导入仍必须能匹配受信任目录条目。

## 安装与恢复

安装使用用户可写的独立版本目录。下载到临时文件，验证后解包到暂存目录，通过类型校验后提交包与原子安装记录。进程间互斥保护写事务。中断、校验失败、磁盘不足或状态提交失败不得破坏当前有效版本。设置和用户录制不属于安装目录。

保留当前及恢复所需版本；缓存可清理。卸载先撤销激活，运行中的原生文件延迟清理。软件升级由外部助手完成，运行中不得覆盖本进程文件。助手等待旧进程退出，启动新版本并等待就绪凭据；失败回滚入口并启动旧版本。系统管理目录不可写时给出可执行的用户目录安装路径，不默默提权。

检查和下载可后台执行，展示阶段、进度、取消和错误。实际替换、启停与卸载必须检查监听、录制及研究任务状态。算力告警不是包或硬件的兼容性上限。

## 界面与持久状态

工具箱中心提供官方目录、已安装、可用更新与软件更新页面，显示来源、当前/最新/待生效版本、兼容原因、依赖、更新说明和操作结果。支持检查、安装、更新、启用、禁用、卸载、缓存清理与离线包导入。软件支持启动后后台检查、手动检查、下载、安装重启、失败恢复；检查失败不影响离线使用。

## 发布与 CI

按用户决定，源码仓库公开，官方目录和安装包使用同一仓库的 Releases。安装包不包含私钥、访问令牌或开发机私有文件。日常编译以本地缓存构建为主，push 和可信同仓库 PR 使用专用自托管 Runner；仅显式发布验证运行 GitHub 托管平台矩阵；创建已验收版本标签不重复触发托管构建。Runner 不处理外部仓库的未受信任 PR。发布签名密钥与客户端公钥分离，签名只发生在发布步骤。

自托管 Runner 的宿主生命周期必须覆盖无人值守任务。在 Windows／WSL 上，仅安装并启用 systemd 服务不足以保证发行版持续存活；Microsoft 明确说明 [systemd 服务不会维持 WSL 实例存活](https://learn.microsoft.com/en-us/windows/wsl/systemd)。部署应配置适合宿主的保活或服务管理方式，并在关闭构建终端后，以真实 CI 任务验证在线状态及执行完成，不能只检查 `systemctl is-active`。自 2026-11-24 起，日常 CI 使用原生 Debian 13 的 `foreshadow-debian13-x64` Runner，由专用 Linux 用户及 systemd 服务运行；当前网络路径依赖 Windows 代理隧道，服务存活不代表 Windows 主机关机后仍能联网。

## 验收要求

本地签名主机需要支持 Ed25519 `pkeyutl -rawin` 的 OpenSSL 3.x CLI。归档复查器先检查 POSIX
成员图，再校验普通文件；拒绝不安全链接、重复成员及符号链接下的归档子项，跨宿主复查时不
物化符号别名，避免 Windows 把别名静默复制成额外运行库。原生验收仍须在目标平台解压并执行
未经改动的实际归档。

macOS 的语言数据放在 `Contents/Resources`，不能把数据目录留在代码签名位置。提供者可声明 `catalog_roots` 候选资源位置；消费者只在已安装工具箱或应用包的边界内解析。包内容由 schema 1 的资源声明组装，目录形状不属于接收机 ID 规则。需要包级资源寻址的 macOS 接收机工具箱声明主体最低版本 0.2.6；旧的相邻目录协议继续支持。

启动凭据须在初始事件循环及布局处理后发出；助手收到匹配的凭据后仍确认进程持续存活，防止“写出回执后立即退出”被视为成功。验收必须包括这种失败与实际用户设置下的重启。Windows 接收机的私有运行库由插件构建声明，随模块放置及随工具箱分发，不能仅依赖开发机 PATH；macOS 构建包也必须通过注册的提供者资源完成接收机模块组装。

测试真实应用升级、启动确认与失败回滚，工具箱两版本安装/升级/停用/卸载及重启生效；验证签名、降级、依赖、平台、断网、取消、越界、磁盘不足、并发与任务冲突。新增独立工具箱与包类型的测试必须证明稳定消费者无需修改。完整既有回归、安装包回放及目标机器已运行版本核验通过后才报告部署完成。

## 维护与发布操作

`tools/distribution/package_release.py` 只读取 CMake 安装目录，输出应用包、两种接收机支持包、功率报告工具箱和未签名 entries；目录包含精确压缩/展开大小、哈希、平台基线与源提交。平台构建不接触签名密钥。工具箱包带有自身的语言目录和依赖文件；应用包不再附送外部研究示例，后者在工具箱中心安装。

正式发布显式运行 `Release platform builds`，填写 `release_tag`、`platform` 以及固定 SHA-256 的 HTTPS 材料地址 `compliance_bundle_url` / `compliance_bundle_sha256`。默认 `reviewed` 在 0.2.13 构建 Windows x64 和 Debian 13 amd64/arm64；`all`、`linux`、`windows`、`macos` 保留给另行准备材料的发布范围。全部材料清单必须匹配冻结的工作流提交，Debian 还须在编译前把已安装 SDK 的源码包身份与审核过的 `.dsc` 文件逐项核对。仅发布验证使用托管 Runner；日常推送仍使用自托管 Runner。打包器要求候选标签、应用版本和资产 URL 相符。便携归档从已验收的基础包组合生成，独立验证可选工具箱。所有待发布平台须在同一冻结提交上通过 CTest、含中文和非 BMP 字符路径中的实际归档检查与 `distribution_package_test` 的真实解包及组件加载检查，才创建不可变的 `v*` 标签；创建标签不再重复运行托管计算。发布者下载并审查这些构建，使用仓库外的 Ed25519 私钥运行 `tools/distribution/sign_catalog.py --entries ... --key ... --output catalog.json`，已有目录通过 `--previous` 验证后合并；发布序号必须递增。签名工具核对编译进客户端的公钥，并再次校验资产哈希与签名。最后将包及签名目录上传到同一正式 Release。私钥不进入 Actions、Git、安装包或远端部署机。

首次安装可使用解压后的安装目录；后续通过“插件 → 工具箱中心”检查、安装并重启应用。停用预装接收机同样在重启后生效。更新受管接收机优先于预装组件；卸载受管更新会恢复预装组件。内置分析模块使用“模块设置”，与应用一起升级。

`signalscope-toolboxes check|list|install ID|enable ID|disable ID|uninstall ID|rollback ID` 为运维入口，与图形中心共享固定信任锚、兼容规则和安装事务；原生模块变更需要重启正在运行的应用。界面在监听、录制、导出、研究或硬件查询进行时拒绝应用变更。下载允许取消，已开始提交的原子安装事务安全完成。

`Release media deadline diagnostic` 仅人工触发，用于正式发布过程中核对 macOS 托管环境的原生等待能力，不属于日常编译或推送检查。它独立比较标准条件变量、相对条件等待、Mach 信号量与绝对等待，不运行媒体编解码器，也不能代替应用验收。正式平台流水线保存完整 CTest 原生日志；受主机定时环境阻断的时延资格与功能通过分开报告。

Linux 通过用户目录安装的稳定启动器与 `.desktop` 入口启动当前版本；Windows 使用 GUI/CLI 两个启动器与用户桌面快捷方式；macOS 使用用户 Applications 下的启动包。启动器不依赖 Qt，CLI 保留参数、标准输出和退出码。更新助手等待旧进程退出并锁定激活，拒绝过期安装状态；启动凭据失败时恢复状态和入口，重新启动原版本。活动模块及激活助手的租约、当前和前一版本共同约束延迟清理。

## 独立接收机服务（0.2.12）

基础应用与可选 SDRplay 服务客户端工具箱分别交付，厂商 API/驱动仅由独立安装的接收机服务加载。
提供者所有的连接描述和请求协议 2 在设备枚举前传递地址，界面、会话和 CLI 保持通用。
固定 BSL SoapyRemote 客户端依赖 SoapySDR 0.8.1，支持离线覆盖
`FETCHCONTENT_SOURCE_DIR_SOAPYREMOTE`。只有声明为随主体捆绑的提供者进入基础归档；
原始 CMake 安装目录是组装暂存树，不是已验收基础归档。SDRconnect 评估、安装、协议、连续性和
许可边界见[接收机服务](receiver-services.zh-CN.md)。
