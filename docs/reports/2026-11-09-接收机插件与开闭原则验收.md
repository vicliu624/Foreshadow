# 接收机插件与开闭原则验收

[English](2026-11-09-receiver-extensions.md) · 简体中文

日期：2026-11-09。范围包含运行时接收机插件、资源本地化，以及按现有扩展轴对整个工程的源码审查和整改。开闭原则约束同一能力契约下的演进，不表示所有未来需求都不需要修改主体。

## 审查结果与整改

| 变化轴 | 发现的问题 | 最终边界与验证 |
|---|---|---|
| 接收机 | 主体链接驱动，设备能力、规则与界面有重复知识 | RTL/AIO2 和 SDRplay 成为两个原生插件，C ABI 隔离控制与二进制样本；第三个插件只依赖公开头和 JSON，独立构建并接入发现、控制、采集、分析和界面，主体哈希不变 |
| 本地化 | 参数构造函数嵌入并排语言，语言菜单和回退有固定语言判断 | 插件维护语言资源和 key；桌面语言包由元数据发现；额外法语资源验证新增语言、逐条英语回退及二进制不变 |
| I/Q 编码 | 多个处理路径假定非 CU8 就是 CI16 | 编解码表统一字节数、归一化、满量程和非法输入处理，新增 CF32；独立接收机使用自身 CF32 编码实现，经过采集、录制、监听通路 |
| 检测器 | 选择菜单、配置评估和处理调度维护平行信息 | 描述、资源及注册接口由检测模块拥有；新增测试检测器进入菜单、评估和调度，消费者不增加算法 ID 分支 |
| 研究工具 | 分析面板导入具体工具、生成 FM 专属参数 | 提供者拥有参数控件、校验与运行函数；分析面板只消费通用协议；外部清单支持参数、联动与资源，通过 JSON 设置文件传递 |
| 事件呈现 | 未知事件缺少通用名称与特征展示 | 通用 display_label/features 支持新增事件；历史证据级别映射冻结，检查禁止继续扩张 |
| 工程约束 | 只有架构说明，缺少扩展行为验收 | 根 AGENTS.md、规格 16、specs/extension-contracts.json、依赖检查、架构检查和独立扩展行为测试共同约束 |

接收机参数描述、联动、硬件校验、推荐、应用顺序和回读均由插件维护。主体负责通用渲染、分析适配和运行负载反馈。推荐值不等同于能力上限，主机算力不构成设备能力上限；存在阻断冲突不能应用。

## 验证边界

接收机是运行时原生插件；内置检测器和研究提供者支持组装注册，未将全部算法改为运行时动态库。新增 I/Q 编码修改所属编解码表及契约，消费者不自行分支。新处理生命周期、相干多通道或全新结果载荷需要显式协议设计与版本升级。

配置评估表示采样与算法的适配条件，不能保证某个空口信号成功探测或解码。RTL 软件连续计数不证明 USB 或硬件没有丢样。未进行完整空口灵敏度、误报率、所有调制的载荷解码或长时间无损验收。

Windows/macOS 的本次构建状态以本次 GitHub Actions 结果为准，不以 Linux/ARM 测试代替。GitHub Actions 预算阻断属于平台外部条件，应和源码测试失败区分记录。
