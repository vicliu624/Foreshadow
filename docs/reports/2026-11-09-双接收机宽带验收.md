# 双接收机宽带改造验收

[English](2026-11-09-wideband-receivers.md) · 简体中文

2026-11-09。按接收机公开能力开放配置，对 RSPdx-R2 和 HackerGadgets uConsole AIO V2 分别验证并部署。

本工程不以 uConsole 的算力定义跨平台参数上限。算力不足通过积压、分析缺口、跳过和接收流错误让用户感知；不静默缩小搜索范围或关闭所选检测器。本次验收不要求这台四核主机无损实时执行所有检测组合。

## 配置结果

| 接收机 | 推荐硬件档位 | 搜索宽度 | 其他调整 |
|---|---|---|---|
| RSPdx-R2 | 10 MS/s | 10 MHz | IF 可自动或手选；10 MS/s 自动选择 8 MHz 的 3 dB IF 带宽，显示边缘滚降及 ADC 标称位数 |
| AIO V2 | 2.56 MS/s | 2.56 MHz | 保留 2.048、2.4、2.56、2.8、3.2 MS/s 等硬件允许档位，3.2 MS/s 显示 USB 连续性风险 |

推荐配置保留频率和检测选择；推荐宽度采用“当前最大可用”模式，随后随采样率联动。固定预设和自定义宽度保留用户请求，超出采样范围时阻止应用。IF 的 3 dB 带宽不再作为搜索范围的硬截断条件。AIO2 通过实际 USB 制造商/产品身份识别板卡，补充 100 kHz–28.8 MHz 的 I/Q 直采模式，直采时禁用无效的调谐器增益。

设置页直接显示数据量、I/Q 格式、ADC 标称位数、IF 和内部分析信道数；十类调制的表格展示配置兼容性与现有解析能力，不虚构成功率。LoRa、FSK、OOK、ASK、FM、BPSK、QPSK、4-FSK、OFDM、CSS 均有覆盖说明。

## DSP 与错误处理

- 共享前向 FFT 的重叠分信道、抗混叠抽取和分数采样率转换保留完整请求频谱，事件映射回原始频率和采样索引。
- 修复最外侧频道的循环 FFT 索引，避免把另一端 RF 频率绕入本频道；多 BW 时外侧频道覆盖最小带宽可完整容纳的位置。
- 修复 SFD 粗候选落在第二个下扫符号时的漏检，以相同结构条件复核前一符号，不降低匹配阈值。
- LoRa 分信道共享工作线程，直接交付浮点样本；FFTW 规划/销毁有共享锁，执行仍可并行。提供 KissFFT 回退。
- 窄带输入维持 256 点 FFT 步进，支持 USB 短读取及任意块边界；高采样率快照和 FM 音频通过对应滤波路径处理。
- Linux 分析线程降低调度优先级，避免满负载分析与采集争用同一优先级。原始采集、频谱及独立录制路径不随分析降采样。
- 界面区分“分析落后，结果延迟”“分析有缺口，可能漏检”和“接收流溢出/中断，停止且数据不完整”，显示积压、分析丢弃、窄带跳过、快照繁忙及 CPU。接收溢出提示检查系统负载和 USB，不把此类故障只归咎于连接。
