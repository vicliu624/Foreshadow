生产算法和协议由 `fbc99ae` 引入；`15e9df5` 补强子载波顺序与训练绑定的整套校验；`22fe498`、`7e0111c` 补充独立复数图点击/定位测试及完成状态设置。**实际评审包源码基准为 `7e0111ce31fb9d6d4a4567121a728abbcdf54a1f`**。此后的报告修改不改变生产程序。工作树为 `codex/waveform-lab`，未发布正式版本或上传签名发布目录。

## 已实现

- BPSK/QPSK：M 次幂 FFT 载波捕获、已知前导相关、分数定时与初始时钟搜索、训练相位斜率频偏细化、矩形/RRC 匹配滤波、训练区有效信道 LS 与有限长 FFE、保留训练区检验、数据判决相位/定时跟踪、候选符号/比特/字节。
- OFDM：CP 与重复训练捕获、整数/分数频偏搜索及细化、CP 内 FFT 定时窗口、两次训练的逐活动子载波 LS 信道和噪声估计、ZF/训练噪声正则化均衡、导频公共相位及相位斜率跟踪、有带限插值的分数 FFT 窗口、深衰落擦除。子载波顺序必须升序，禁止排序后悄悄改变训练/导频值绑定。
- EVM：在均衡和相位校正后的数据符号计算 RMS/峰值，按平均参考功率归一化；明确已知数据或判决参考；训练、导频及无效点不进入数据测量。显示有效/排除点数。有效点不足八个、排除比例超过 20% 或失锁时不给出可用 EVM。数据参考不参与同步、信道和均衡估计；低 EVM 不升级应用帧校验状态。
- 通用工作流：恢复协议 v2 的复数平面、组/有符号坐标、生成参考和标量测量；通用星座/信道视图、值表、点击与输入定位、证据 v2 导出、恢复配置 v2 和外层分析 v8 保存重开。v1 提供者及旧档案继续兼容。图形最多显示 16384 个点，完整表格/证据和 EVM 不受绘图抽样影响。

算法、完整参数校验和中英文资源由各恢复提供者拥有，只有恢复注册表增加组装；界面、后台和导出没有按 PSK/OFDM ID 增加行为分支。独立 `independent.vector-plane` 提供者使用相同协议完成测量显示、法语资源增量/英文回退、复数点点击、精确输入定位与配置恢复。

## 数值与契约证据

`coherent_recovery_contract` 的发射真值独立于接收实现：RRC 由频域平方根升余弦响应数值积分产生，OFDM 使用显式逆 DFT / 连续时间子载波求值。测试包含分数起点、频偏、相位、多径、采样偏差与噪声，逐点重算 EVM 和峰值，并检查所有有效载荷判决。下表具体数值取 Linux 基准日志；Windows 同一真值和容差检查通过，不要求不同标准库产生逐点相同的随机噪声。

| 输入真值 | 已验证结果 |
| --- | --- |
| BPSK/QPSK，矩形与 RRC，128 个数据符号，79.3 Hz 频偏、分数起点及两径 | 四组载荷判决均正确；RRC BPSK/QPSK RMS EVM 约 4.442% / 4.006% |
| RRC QPSK，1024 数据符号，输入时钟 +900 ppm，−163.1 Hz 频偏 | 1024 个有效判决正确；RMS EVM 约 11.958%；这是该输入下的测量，不代表通用性能保证或 ppm 测量精度保证 |
| OFDM 64/16，32 数据符号、1536 数据子载波点，+400 ppm、−1.27 子载波频偏及两径 | 1536 个有效判决正确；RMS EVM 约 1.694%；捕获频偏约 −1.270454 子载波 |
| 独立物理两径频响 | 除去未校准的共同复增益后，估计频响归一化 RMS 误差小于 1% |
| OFDM 已知双陷波 | 每个数据符号的 ±16 子载波保持未知，八个数据符号共排除 16 点，不能导出为有效字节或有效 EVM 点 |
| 参考隔离 | 切换已知数据参考/留空不改变接收的复数点；错误已知参考不会被拟合消除 |
| 负例与预算 | 错误训练、纯噪声/静默、间断、取消、非法参数和独立资源限额均拒绝或保留无效状态；未用补零伪造观测 |

上述数据是明确配置的合成真值，不是实体射频接收性能、盲协议识别或长期无损的证据。有效信道是分析时钟和声明脉冲下的估计，不是射频校准。自然相位编号和高位在前的字节映射均明确保留。

## 发现与修正记录

1. 长 OFDM 数据的线性分数插值会产生幅度误差；改为先消除频偏的带限分数采样，并使用独立连续时间子载波真值验证时钟跟踪。
2. 多径 CP 相关峰可能导致 FFT 窗口偏晚并泄漏下一符号；将 FFT 锚点放在 CP 内，训练估计吸收相位斜率；双陷波测试确保不会把此误差当作有效载波。
3. Windows 首轮出现八项恢复/后台失败。确认本机 MSVC `/showIncludes` 前缀编码与 Ninja 不匹配，旧对象记录为 0 个头文件依赖，协议结构变化后混入旧布局。统一 UTF-8、重新检测编译器并重编全部 292 个项目对象后，同一源码全量通过；LoRa 编解码对象已记录 56 个依赖，包含恢复头。固定依赖下载和第三方构建树保持不变。参见 [Ninja 的 MSVC 依赖协议](https://ninja-build.org/manual.html) 与 [Ninja 上游编码讨论](https://github.com/ninja-build/ninja/issues/613)。
4. 最终 Windows 第一轮出现一次既有工具箱卸载断言失败：`Uninstall did not preserve the package outside the loading directory`。失败日志保留为 `logs/native-7e0111c/windows-tests-first-run-uninstall-failure.log`；后续相同二进制完整 100 项回归通过。未证明其原因，不把它记作已修复的产品缺陷。实际包事务另行核对。
5. 新增独立图点击测试最初没有设置宿主的完成可用状态，导致定位动作仍禁用；补齐测试状态并明确断言动作可用。最终三种原生尺寸验证点击后的来源范围，没有通过放宽来源断言规避失败。
