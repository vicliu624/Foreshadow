# LoRa 实时丢弃与共享调度验收

[English](2026-11-10-lora-scheduling.md) · 简体中文

## 用户现场

31.42 上的 0.2.6 GUI 在 100 MHz、10 MS/s、10 MHz 搜索宽度下监听，用户尚未启用 FM 音频。停止后取得的状态为：

| 阶段 | I/Q 对数 |
|---|---:|
| 接收机交付 | 146,423,808 |
| 录制路径处理 | 146,423,808 |
| LoRa 主分析处理 | 145,539,072 |
| LoRa 主分析丢弃 | 884,736（约 0.604%） |
| 辅助分析处理 | 146,423,808 |
| 辅助分析丢弃 | 0 |

主队列达到 16 MiB 上限，形成 18 次分析缺口。界面当时显示约 3.56 个等效核心、整机 CPU 15%；这不是 FM 音频播放引起的负载，也不能据此认为整机算力已经耗尽。驱动没有硬件样本计数器，以上只证明软件已知的传递与丢弃，不能保证硬件绝无丢样。

## 所有者、原因和修正

变化轴是检测器的工作调度与 DSP 信道化；协议所有者为 LoRa 检测模块和公共 DSP。接收机插件、通用会话、界面及 CLI 的行为分支均不需要修改。

原实现把整个子频段交给单个工作线程，该频段里的多个带宽、扩频因子及 I/Q 方向搜索串行执行。一个频段繁忙时不能使用其他频段的空闲线程；信道化又在这些任务前串行运行。用同一段实测录音连续输入 6 秒，基线 LoRa 分析约需 6.71 秒，其中独立测量的信道化约需 2.08 秒。

- 信道化在构建计划时预计算连续 FFT 索引段，保留 RF 边缘裁剪和原有别名求和顺序，移除热循环中的重复索引与边界判断。该阶段约降至 1.57 秒。
- LoRa 保留每个信号模型的独立历史、FFT 缓冲及结果桶，使用一个有界持久线程池在不同子频段的搜索模型间分配任务，仍按频段与模型顺序合并结果。线程预算由已有配置决定，不再被子频段数提前截断。
- 每批输入先完整校验各检测器的时间位置，再准备共享只读输入、并行执行和回收结果。内部输入分段保持 131,072 个样本的上限，任务数量受模型数约束。

相同 10 线程预算、相同 6 秒录音的 LoRa 分析降至约 5.05 秒，诊断事件数保持 2,134。该数值是目标机器上的一次吞吐对照，不是所有主机或所有 RF 场景的固定性能。

没有缩小搜索范围、减少所选模型、提高检测门限或扩大默认分析队列。曾试验 FFTW 的测量式规划，但收益不足且增加启动成本，未采用。

## 持续实机验收

在相同 RSPdx-R2、100 MHz、10 MS/s、10 MHz 搜索宽度、全部实时检测器开启的条件下，使用 16 个推荐工作线程和默认 16 MiB 分析队列，持续输入 180 秒：

| 指标 | 结果 |
|---|---:|
| 接收机交付 | 1,800,000,000 对 |
| 录制路径处理 | 1,800,000,000 对 |
| LoRa 主分析处理 | 1,800,000,000 对 |
| LoRa 主分析丢弃／缺口 | 0／0 |
| 辅助分析处理 | 1,800,000,000 对 |
| 辅助分析丢弃 | 0 |
| 主队列载荷峰值 | 2,686,976 字节（约 2.56 MiB） |
| 辅助队列载荷峰值 | 1,835,008 字节（1.75 MiB） |
| 驱动短读／超时 | 27,917／0 |

运行快照约使用 8 个等效核心。短读没有缩小队列预算，也没有被错误标成软件丢弃。停止后各阶段排空，样本计数守恒。原始 RF 和机器状态文件只保存在忽略的测试目录，不进入源码及安装包。

这证明上述场景的 180 秒软件连续性；不保证无限时长、任意外部负载、任何信号均能检出或解析，也不覆盖 FM 音频输出。驱动回读仍为 10 MS/s、8 MHz IF 滤波器，数字搜索跨度不代表 RF 通带完全平坦。

## 回归与交付边界

新增同时存在的两个远离中心的信号，在 1 与 12 个工作线程下产生完全一致的检测证据、源样本时间及搜索工作计数。另验证整批非法输入不能部分推进其他频段、共享和独立输入能保持各自时钟，以及静默输入不产生证据。

本地 WSL 已执行 45 项 CTest，全部通过。目标机首轮 45 项回归无失败，其中 3 项隔离 SDRplay 后端／界面测试因环境条件跳过；实际 RSP 连续输入另按上述硬件路径验证。
