# DTMB 识别与实收扫描验收

[English](2026-11-11-dtmb-detection.md) · 简体中文

日期：2026-11-11。实现提交：`d58015a51a26dc599200ded8ebc7e90a2b447df9`。本报告区分结构识别、现场接收、持续处理与发布验证；配置兼容不等于成功接收或电视内容解码。

## 已验证的识别与扩展

依据 GB 20600-2006 的 PN420、PN595、PN945 与 3780 符号帧体检查 DTMB 结构。算法、输入要求、描述、事件特征及中英文资源归属 DTMB 提供者；主菜单、接收评估和事件视图通过通用描述接入，没有增加按 DTMB ID 分派的界面分支。

快照扩展协议 v2 增加提供者声明的周期观察。各观察策略有独立任务槽，忙时跳过、完成、待处理与处理中载荷字节分别统计。独立提供者契约验证了恒定输入、任意样本起点、不连续样本、超载，以及故意挂起一个策略时另一策略继续执行。

标准位向量测试独立核对 PN 多项式方向、寄存器输出、周期和 PN595 截短。独立发射夹具使用寄存器图和标准初态生成三种帧头，覆盖单载波符号体与 3780 点多载波随机帧体、8 / 9.6 / 10 / 10.666 / 20 MS/s、频偏、分数定时、6 dB 信噪比、多径及 CU8 / CI16 / CF32。两个相同 PN 模式、不同中心频率的完整频道可以同时产生事件。负例包括噪声、单音、FM、CP-OFDM、其他 PN、连续 PN、单个合法帧头及错误帧间隔。

这些夹具验证帧结构，不包含完整系统信息、信道编码或电视节目。因此不把夹具通过写成全标准解码通过。

另用独立项目公开的[重调制样本目录](https://raw.githubusercontent.com/wiki/ningzichun/dtmb-sdr/Samples.md)验证。样本声明 16 MS/s、PN945、profile 22；原 ZIP SHA-256 为 `1982a40508112e32397b6b06c3f41f63ff3f17336ccd6dfd4b05a6752ade4853`。按其已声明的 CI8 编码转为 CI16 后，CLI 和实际桌面回放均识别到 PN945、18 帧、约 0.911 的 PN 相关度，首个检查帧位于源样本 10000。该数据是重调制参考，不是本次现场接收正例，也不意味着 AMS 已解码 profile 22。

高采样率文件扫描还修复了一处读取边界问题：扫描窗口不再直接作为回放读取块，读取块遵守 4 MiB 上限，任意分块仍保留扫描重叠和绝对样本坐标。16 MS/s 的 CI16、CF32 回归通过。

## 现场扫描：尚无 DTMB 实收正例

RSPdx-R2 使用 10 MS/s、自动增益、实际 8 MHz IF 滤波器。每个频点先稳定 150 ms，再保存 50 ms、500000 对 CI16 I/Q；DTMB 识别检查其中的 12 ms 连续窗口。

共核验 105 份有效采样、60 个不同中心频点。A 端口 69 份，B 端口 36 份；A 端口覆盖所有本次频点，B 端口补查主要 UHF / VHF 与 570–602 MHz。没有通过 DTMB 帧结构确认的事件。有效采样中接收机报告的拒绝样本与读取超时均为 0；驱动没有提供硬件样本计数器，不能据此保证硬件绝无丢样。

| 扫描类别 | 中心频率 MHz |
|---|---|
| 主要 UHF 候选 | 474–562，每 8 MHz；610–698，每 8 MHz |
| VHF 候选 | 171–219，每 8 MHz |
| 低 VHF 补充 | 52.5、60.5、68.5、80 |
| 额外频段排查 | 570–602，每 8 MHz；706–858，每 8 MHz |

频道参考来自[广电总局公开指南](https://www.nrta.gov.cn/module/download/downfile.jsp?classid=0&filename=324831b10cc44c279f38de1637afe01a.pdf)及[公开频道栅格](https://www.nrta.gov.cn/module/download/downfile.jsp?classid=0&filename=6d7f314d26524eb896d2473fbcd65f58.pdf)。额外排查不表示这些频点当前都获准或实际用于 DTMB。[700 MHz 调整通知](https://wap.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2020/art_e5389a57ece640b4bd1b69dd74cff8a7.html)与旧频道表分别解释，不能将移动通信 OFDM 认成 DTMB。

与原生测试并行的首轮补扫曾有 16 次设备暂不可用；回归结束后重新完成该组 25 个频点，全部取得有效样本。原始失败日志与成功样本均保留，没有将设备不可用当作无信号。当前天线类型、实际安装与当地覆盖条件未确认，因此结果不能证明当地没有 DTMB 发射。

## 持续输入与资源

测试主机为 Ryzen 9 3900X、24 个逻辑处理器。GUI 运行 210 秒，RSP 实际提供 207.985 秒、2,079,850,496 对 I/Q。100 MHz 中心、10 MHz 搜索，LoRa、窄带、快照检测和静音 FM 音频并行。射频输入为广播 FM 环境，用于持续负载及 DTMB 负例检查；这不是持续 DTMB 实收证明。

| 阶段 | 本轮结果 |
|---|---|
| 采集与录制 | 均处理 2,079,850,496 对；接收拒绝 0，超时 0 |
| 主分析 | 处理 2,079,850,496 对；分析丢弃 0 |
| 窄带分析 | 处理同量输入；跳过样本、跳过块和输入缺口均为 0 |
| 能量触发快照 | 129 触发、129 完成、忙时跳过 0 |
| 周期观察快照 | 208 触发、208 完成、忙时跳过 0 |
| 快照最终载荷 | 待处理 0 字节；处理中 0 字节 |
| FM 音频 | 输入拒绝、输入缺口和 PCM 延迟丢弃均为 0；5 次输出欠载均恢复，未进入错误状态 |

早期候选共用一个任务槽，曾出现 101 个忙时跳过窗口；按观察策略隔离后，本轮 337 个窗口均完成。报告保留这项对照，不将跳过分析窗口称为硬件丢样。

驱动返回了 32255 次短读，长度最小 448 对、最大 16384 对；短读按实际载荷处理，没有按完整 USB 块估算内存。本轮状态快照可见整机 CPU 比例和等效核心数；不能把低整机百分比等同于每条串行任务都有余量。单次 210 秒验证不构成长时间或所有主机实时无损保证。
