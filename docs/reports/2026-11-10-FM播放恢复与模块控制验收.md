## 现场问题与边界

用户在广播 FM 事件上播放声音后，状态栏提示播放因错误而停止，且没有独立的音量、静噪、设备及开始／停止界面。

在 192.168.31.42 的实际音频输出上，以音量 0 重放实测的 10 MS/s I/Q，旧实现复现为 `stream_failed=false`、`QAudio::UnderrunError=3`、`QAudio::IdleState=3`。解调器没有失败；旧桌面输出把短暂欠载当成致命错误。任意非零起始样本号原本就是支持的，不是本次故障的原因。

变化轴及所有者如下：

| 变化轴 | 所有者 | 稳定消费者／组装位置 |
|---|---|---|
| 实时研究生命周期 | `LiveResearchProvider` v1 | `LiveTools`；`live_registry.cpp` 组装 |
| FM 参数、界面、校验、偏好与文案 | FM 研究提供者及其 JSON 资源 | 主窗口和工作区仅承载通用组件、事件操作及诊断 |
| FM 解调、输入预算及连续性 | FM 调制模块、I/Q 编解码接口 | 提供者传递规范化输入及实际来源参数 |
| 音频预缓冲、设备、音量、静噪和恢复 | FM 提供者自己的播放实现 | 界面读取已发布快照，不拥有音频设备 |
| 频谱栅格绘制 | 显示提供者 | 主窗口不参与按像素聚合 |

协议 v1 是新增的、随应用编译的 C++ 生命周期能力。现有外部研究工具的快照 IPC 不能直接表达实时 I/Q、原生 QWidget 或持续播放；本次没有声称这些外部工具自动具有上述能力。内置 FM 随应用发布，不是独立可替换的 ABI 工具箱。

## 实现与使用闭环

先开始接收机监听，再在广播 FM 事件菜单选择“通过 FM 模块收听”；提供者打开自己的工作区面板并选择事件频率。也可以在 View／视图中打开“FM 接收与播放”，手动输入当前数字 I/Q 内的频点。完整信道超出输入、缺少输出设备或参数冲突时，禁止开始并显示原因。“接收中心”按钮可以恢复使用当前接收中心频率。

面板提供开始、停止、应用／重新调谐、输出设备与刷新、应用音量、静音、静噪及门限、去加重与频偏归一化、推荐值恢复、信道电平、信噪比估计、PCM 电平、缓存时延、输入丢弃、输入不连续、输出欠载和 PCM 丢弃统计。真实错误持久显示错误代码和详细信息。隐藏面板继续播放；停止音频不停止接收机；停止接收机会停止音频。原有布局按有效保存状态恢复，新面板自动进入 View 菜单。

信噪比采用信道滤波后的二阶／四阶矩恒包络估计，按 50 ms 窗口平滑。它会受干扰、衰落和削顶影响，不是校准仪器结果；调节静噪门限不会提高射频信噪比。当前输出为 48 kHz 单声道 FM 音频，广播立体声导频证据不等于已经实现立体声或 RDS 解析。

输入使用按实际载荷预算的 SPSC 字节环，仅在不连续边界保存有界元数据。短读不缩小缓冲时间，DSP 读取和复制不占用采集入队的互斥锁。初期候选在持续测试中发现约 1.2% 的锁竞争丢弃，已淘汰且没有发布。音频设备和供给定时器进一步迁入独立输出线程，界面繁忙不再阻止 PCM 写入；状态读取只复制小型快照。输出欠载重新预缓冲后恢复，不与输入拒绝、PCM 延迟丢弃或解调失败混为一谈。

频谱绘制按可见像素聚合，保留每列的峰值和最低电平，避免在狭窄面板内给每个 FFT 点生成相互重叠的抗锯齿描边；没有改变原始 FFT、检测输入或接收带宽。

## 已验证

- 本地完整 49 项 CTest 通过，包括依赖、开闭原则、本地化、旧录制、回放、接收机参数、分发和桌面回归。
- 独立实时研究提供者在不修改宿主的条件下注册、接收借用 I/Q、添加未知事件操作、进入 View、停止、发布诊断，并验证失效隔离和会话代次。仅增加荷兰语 FM 资源即可显示新标题，缺失 key 按英语回退；资源路径包含中文和非 BMP 字符。
- 2.56／10 MS/s、CU8／CI16 的宽带 FM 解调覆盖大样本序号及短读，PCM 与同一输入的整段处理一致。注入不同噪声的参考信噪比验证估计单调变化及误差边界。
- 在整段载荷可以容纳的预算内，数千次极短回调突发输入无拒绝、无不连续，并保持与离线解调相同的 PCM。既有缺口重置和环形回绕回归通过。
- 实际音频设备测试覆盖 300 ms 来源暂停后的恢复、主界面暂停处理事件 300 ms 时音频输出仍前进、音量、静音、静噪开关和输出重开。自动测试音量为 0，不改变系统音量或默认设备。
- 31.42 原生完整 49 项测试无失败；模拟 SDRplay 的 3 项测试按环境条件跳过。真实 RSP 另外进行持续输入验证。
- 本地真实安装包在含中文及非 BMP 字符的安装目录运行，完成应用、接收机、研究资源加载、桌面回放及四个工具箱真实归档安装事务。

## 桌面环境与未验证范围

31.42 的窗口管理器曾卡在 GLX 查询，连独立 Qt 和 X11 探针的新窗口也不能映射。按用户明确授权重启 Xfce 窗口管理器后，仍在相同 GLX 路径阻塞；当前会话改用 `xfwm4 --compositor=off` 后，新窗口正常映射。系统原有 `use_compositing=true` 偏好已恢复，关闭合成仅作用于当前管理器进程；已有应用保留。

该机原生 X11 读窗图像仍返回黑图；应用自己的 Qt 抓图可以完整渲染界面。用户当时没有查看该桌面，故没有将物理屏幕显示和人耳听到声音写成已验证。自动音频测试为静音，实际扬声器连接与默认 IEC958 设备是否符合用户期望需要实际使用确认。

系统代理沿用用户原配置，不加入临时开发机隧道。连接 GitHub 失败应明确显示网络错误，不影响已经安装的离线能力。
