# 长期监听与事件存储

[English](08-continuous-monitoring-and-event-storage.md) · 简体中文

## 1. 当前默认行为

当前支持有界内存/磁盘的持续监听，但尚无通用 24 小时实时无损及硬件无丢样验收结论。下文观察启动、PID、计划到期及失败属于带日期的历史证据，不能视为当前仍在运行；旧观察已明确失败，新启动记录不等于终态通过。缓冲及短时验证结果按各自条件保留。

长期监听使用 monitor 命令，默认运行至用户停止（seconds=0）。采集回调不写磁盘，录制队列和分析队列均有容量限制。原始预触发数据只在内存环形缓冲中保存，超过时长或容量就覆盖，不生成持续增长的临时 I/Q 文件。

仅 lora_structure_match 触发原始片段保存；css_candidate 只计数并丢弃详细候选，不持久保留其原始样本。结构匹配仍可能误判，因此所有已保存事件也受容量和期限约束。

| 参数 | 默认 | 含义 |
|---|---|---|
| ring-seconds / ring-mib | 8 秒 / 32 MiB | 双重约束，实际样本上限取较小值 |
| analysis-queue-seconds / analysis-queue-mib | 5 秒 / 16 MiB | 分析突发缓冲双重上限，超过后仍明确计数丢弃 |
| queue-blocks | 64 块 | 采集来源队列容量；不再同时决定分析队列 |
| pre-seconds | 0.5 秒 | 相对候选首次观察点请求的预触发长度；不足则标记缺失 |
| post-seconds | 0.5 秒 | 末次活动后的安静尾部目标；带内能量持续时继续补录，受文件上限约束 |
| max-event-seconds / max-event-mib | 8 秒 / 32 MiB | 单段双重上限，先到即停止；持续事件不能无限延长 |
| quota-mib | 1024 MiB | 受管事件容量配额，创建新片段前预留其最大容量及元数据余量 |
| max-files | 256 段 | 超限优先淘汰旧事件 |
| keep-hours | 0（默认不按年龄删除） | 需要时可设 168 等期限；容量/数量达到上限时仍淘汰最旧事件 |
| reserve-mib | 256 MiB | 保持系统余量，不足则拒绝新增录制 |
| 独立录制缓冲 | 32 MiB | v3 代码版的固定有界原始队列，用于隔离录制 I/O 停顿；不是磁盘临时文件 |

2 MS/s、cu8 时原始数据约 4 MB/s，8 秒预录制约 32 MB 内存。不会因为运行 24 小时而自动生成约 346 GB 的全天原始数据。匹配事件很多时，旧事件会按策略被删除，不能理解为无限归档。

## 2. 使用

```bash
./build/signalscope monitor --output lora-events --frequency 470500000 --rate 1750000 --gain 38.6 --workers 4 --threshold-db 11 --seconds 0
```

可用 seconds=90000 设置 25 小时预算；零表示持续至停止。有限时长也仍是事件录制，不连续写全时段原始数据。monitor --input 文件 可按原速验证相同处理链，事件注明录制来源，不能当实时 RF 结果。

停止后输出摘要，运行中固定更新 monitor-status.json，不追加无限日志。状态包含采集/分析样本数、丢弃分析样本数、分析缺口、内存环形缓冲、保存与淘汰计数及最近最多 32 条 LoRa 结构事件。

## 3. 清理边界与异常

自动仓库有自身标识，只接受新目录或有效已有仓库；加互斥锁，拒绝同时运行两个写入者。只清理该仓库下带自身事件标识的 event-* 目录，拒绝符号链接，不能将任意导入目录作为清理对象。

同一捕获区间的事件可合并，但受单文件上限限制。中断、分析缺口、预触发不足和大小限制保存在元数据。原始捕获配置与事件的全局样本索引保留；保存时刻不冒充射频到达时间。

原始环形缓冲与录制由采集来源路径独立维护（source_owned_ring_v2）。若 CPU 无法实时处理，分析队列拒绝新块并明确计数，下一块重建检测状态，不将不连续分析样本拼成 LoRa。分析缺口不再人为截断仍连续到达的原始录制；但缺口内的信号可能未被识别或触发保存，因此不满足全覆盖检测目标。分析结果晚于原始环形历史范围时，仍可能丢失前导部分，须核对 pretrigger_truncated。USB 无硬件序号，不能用软件路径连续声称硬件绝无丢样。

后续代码版 independent_capture_writer_v3 进一步把环形缓冲、写盘、淘汰和状态文件写入移到独立录制线程，采集同时向分析和有界录制队列供数。分析状态采用非阻塞的存储快照，录制忙时 storage_status_stale=true；这时射频测试不得把旧快照当作已空闲。晚到的结果按确认样本位置等待相应原始块，正常结束先排空分析，再排空录制，最后发布最终状态。

recording_processed_pairs 表示录制路径消费的位置，包含随后被环形缓冲丢弃的未确认样本，不等于磁盘保存量；实际保存量看事件文件。recording_lag_seconds 和 recording_queue_high_water_blocks 用于观察 I/O 积压。录制缓冲满、文件错误仍明确停止，不静默覆盖；result_dropped_groups 与 result_dropped_events 分别统计结果组和单事件丢弃。此版已通过本机/ARM 阻塞隔离及错误传播回归，并已部署；目标机完成 300 秒软件计数无丢弃现场验证，仍未完成真正长期稳定性和全部识别质量验收。

常规模式的录制触发队列只接收 LoRa 结构事件，初步探针保留在最近候选显示，并通过 diagnostic_events_not_recorded 计数。显式诊断模式例外。初步 Chirp 探针上报按每个候选模型约 0.25 秒一次节流；这只限制诊断输出，不减少结构检测输入。最终上限截断需查看 possibly_truncated 与 quiet_tail_observed，不能仅凭文件存在认定完整包。

写盘/元数据错误采用明确失败状态并停止本次监听，避免持续产生损坏文件。长期无人值守的自动恢复和 UI 提示仍需结合后续故障测试完善。

## 4. 验证要求

覆盖无信号不写 I/Q、仅 CSS 不保存、有效 LoRa 保存与重放、预触发裁剪、持续触发文件上限、数量/容量/期限淘汰、重启恢复、锁冲突、低磁盘、分析缺口和超过 24 小时的 64 位计数。

短时功能测试与模拟样本计数不能替代 24 小时真实长稳报告。目标机完整长稳、真实 LoRa 捕获率及存储寿命尚待验证。

## 有界突发缓冲的配套约束

1.75 MS/s 时分析队列最多约 4.79 秒；预录窗口为 8 秒、约 26.7 MiB。它们必须配套考虑：仅增加分析队列会让判定晚于原始包头淘汰，导致能识别却录不全。默认采集队列仍为 4 MiB，独立录制队列仍为 32 MiB；不增加连续磁盘写入，正常磁盘配额仍为 1 GiB。

允许短时分析延迟不代表提高了持续处理能力。界面在延迟超过 0.2 秒时显示分析延迟，超过 0.5 秒变色；溢出仍计数。新观察器按已声明分析队列时间、一个在处理批次及 0.25 秒余量检查，旧版没有该字段时仍使用两秒限制；录制积压限制仍为两秒。掉样计数条件没有放宽。

本机测试覆盖分析暂停两秒、队列高水位超过旧 64 块、最终零分析丢弃和录制逐字节一致，以及六秒晚到判定的包头保留。它们不代替目标机实时和 24 小时验证。

缓冲回归补充：分析暂停改在明确的分析进度回调中注入，写盘暂停使用有期限的条件变量屏障，避免依赖机器快慢或偶然调度。更新后的 LoRa/捕获回归通过（19.44 秒）；全四项此前通过。状态另报告一个在处理批次的样本时长，观察器的分析延迟预算为队列时间 + 在处理批次 + 0.25 秒，掉样计数仍须不增加。v4 源快照 SHA256 已复核，未丢弃弱信号研究。
