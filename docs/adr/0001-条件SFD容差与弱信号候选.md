# 条件 SFD 容差与弱信号候选

[English](0001-conditional-sfd-and-weak-signals.md) · 简体中文

日期：2026-11-04。状态：条件 SFD 容差已实现并完成 ARM 与重复射频验证；弱候选部分仍是诊断原型，未进入接收器。

## 已采用的决策

继续要求连续六个前导码 Chirp、同步网格、两个一致的下 Chirp、四分之一结尾及结束。前导码/同步要求不降低；只有已存在连续前导码时，下 Chirp 峰均比允许比主门限低 2 dB，局部峰突出度要求不变。

理由来自自有发射器的真实样本：前导码强度约 13–14 dB，两个下 Chirp 中约 9.93 dB，四分之一结尾约 8.14 dB，结束后约 -10.72 dB。统一 11 dB 门限漏检，整体降为 9 dB 可以检测，但会同时扩大普通候选入口。条件容差只作用于后续 SFD 判定，不改变正常无信号时的探测门限和频率覆盖。

回归片段及 SHA256 位于 tests/fixtures/lora-sf7-weak-sfd，测试不传入发射频率、BW 或 SF。Windows 四组、ARM 五组测试通过；噪声、单音、纯 CSS、截断或延长 SFD 仍不判作 LoRa。算法标识更新为 dechirp-fft-structure-v2，结果保存实际下 Chirp 门限。

240 秒实机重复试验中软件队列无丢弃。-9 dBm 下中心 BW500/SF7、短前导码均为 3/3，低侧边缘 2/3，高侧边缘 0/3。高侧边缘 0 dBm 对照为 3/3，不能用对照替换原失败记录，也不能据此排除通带衰减。绝对接收灵敏度仍未校准。

## 剩余问题和诊断原型

高侧边缘样本在前导码期间有重复峰，但部分符号仅约 8–12 dB，存在全局最大峰跳到其他频率的情况。降低结构门限不等于降低当前 13 dB 的候选种子门限，故不能仅根据低门限仍失败就认定没有信号。

可利用相隔半符号的两个现有 Dechirp FFT：对于重复上 Chirp，主要谱峰位移应约为 ±BW/2，即 ±2^(SF-1) 个 FFT bin；再检查相隔一个符号时的重复性。工具 tools/probe_half_phase_pairs.py 已在保存的弱样本上输出候选，但使用已知 BW/SF，未验证完整结构，绝不是盲检成绩。

三点一致性原型在高侧样本保留了已知发送时段的候选，并减少了其他时段候选；短前导码背景仍存在多个候选。后续不能直接把这些候选提升为 LoRa，必须继续以原始数据复核完整前导码、同步和 SFD，并验证虚警与 CPU 开销。

另需检查边缘时下 Chirp 的峰选择：现有实现先选局部最大，再检验推断中心是否在搜索范围内。较强的带外干扰峰可能挤掉较弱但几何上有效的峰。可研究在选择时提前使用相同的中心范围约束，保留量化容差，最终覆盖仍不得缩小。

任何后续变更都必须保持 1 MHz 同时中心搜索、三种 BW、SF7–12 及双 I/Q 极性，并重新执行正反例、实测回归、边缘重复发射和实际吞吐验证。原型只用于下一步假设检验，不属于已部署能力。

## 同步设计参考

2026-11-04 查阅了 [EPFL 的 LoRa PHY 说明](https://www.epfl.ch/labs/tcl/resources-and-sw/lora-phy/)与其指向的 [gr-lora_sdr 帧同步实现](https://github.com/tapparelj/gr-lora_sdr/blob/master/lib/frame_sync_impl.cc)。该接收链明确执行采样时序与载波频偏的估计和校正；实现也使用缓存前导码进行后续估计。因此下一步应检查候选窗口、时序和频偏细化，而非只把所有门限一并降低。

这些资料是设计参考，当前没有移植其代码或引入 GNU Radio 运行时，也不把其接收性能作为 AIO2 的实测结果。我们的未知频点、多 BW/SF 搜索与设备资源约束仍须单独验证。

## v3 实验：精细同步与 SFD 转换联合验证

半符号三点候选现在仅用于激活密集搜索。最终事件统一经过六个前导码的载波/时序细化、相干度与邻频检查、两个同步符号网格和两个下 Chirp 及四分之一段验证。不能从候选激活直接判定 LoRa。

真实高侧录制显示，进入数据符号后，短窗的下 Chirp 投影可能残留，仅以 5 dB 下降检查结束会漏检。实验版因此比较下 Chirp 长度 1.875、2、2.125、2.25、2.375、2.5、3 符号与后续未知上 Chirp 的联合匹配。只接受 2.25 模型优于备选的候选，不恢复符号字节，也不解析协议。候选数据符号来自 FFT 的八个峰及相邻位置，计算量有界，不遍历完整载荷。0.5% 分数优势是经验特征门限，尚无虚警概率标定。

事件需要下 Chirp 起点后四符号及细化余量，confirmed_at_sample 随之更新。每次尝试总投影上限 64 Mi 点，前导码时频细化最多使用 48 Mi，剩余给最终转换检查。中心优先的候选顺序防止长 SF 在有效候选到达前耗尽预算。

Windows 四项测试已通过，包括真实高侧片段及六类错误长度各两个偏移；ARM 和新实发仍需复核。部署以前必须确认原生测试、未知 BW/SF 实发矩阵、队列和运行负载，不能只凭单个真实片段恢复而上线。此前 v2 的部署状态不因本节自动改变。
