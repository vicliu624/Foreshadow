# 接收机能力与配置联动

[English](13-receiver-capabilities-and-configuration.md) · 简体中文

改造覆盖 RTL-SDR 和 SDRplay 的能力查询、参数联动、桌面反馈、配置应用与回读，以及[宽带接收与多速率分析](14-宽带接收与多速率分析.md)。RF/LNA、Bias-T、陷波、HDR 等独立控制项仍需分别扩展，不能将它们视为已经实现。

## 现有架构与新增边界

桌面通过独立的 `signalscope` 子进程查询设备，监听会话通过接收机注册表调用适配器。采集、主分析、旁路分析和录制使用独立有界队列。厂商库只链接到接收机模块，Qt 只用于前端。

- `adapters/receivers/configuration` 定义可序列化的设备能力与纯硬件配置规则，不依赖 Qt 或调制检测器。
- `backend/sessions/receiver_configuration` 在硬件配置计划上增加监听分析要求，由桌面预览、CLI 预检和监听启动共同调用。
- 接收机的 `configure` 与 `stream` 共用参数应用和回读实现。RSP 驱动在流激活时才初始化硬件，`configure` 会短暂激活接收流、确认启动并再次回读，随后释放设备，不交付或保存 I/Q。设备关闭后设置未必持久保留；监听启动会再次配置和回读。
- 桌面只展示校验结果、编辑用户请求及异步调用 CLI；驱动错误仍由适配器转换。

## 能力与来源

`probe` 保留既有字段，新增版本为 1 的 `capabilities` 对象，包含型号、格式、采样率范围与常用档位、推荐档位、频率范围、滤波档位、天线、手动增益，以及来源标记。推荐采样率不再过滤驱动报告的档位。连续范围可接受未列出的整数采样率。

SDRplay 优先使用 SoapySDR 查询；RSPdx/RSPdx-R2 的天线 C 上限及 ADC 标称位数补充自厂家规格，均属于规格信息。ADC 位数不等于 ENOB，不等于 I/Q 数据格式，也不表示软件测量到了硬件内部采样率。低于 2 MS/s 的 RSP 输出不推导 ADC 位数。

librtlsdr 未提供通用频率范围枚举，适配器根据它报告的调谐器类型提供标称调谐范围。未知型号保留未知信息并由驱动在应用时核验。只有 USB 制造商及产品身份匹配 HackerGadgets AIO V2 的板卡，才补充制造商公开的 100 kHz–28.8 MHz 直采路径。自动输入在调谐器范围之外的短波频段选择 Q 路，也可明确选择 I/Q 路；应用时检查实际输入模式。直采时不应用调谐器增益。此识别不等于短波通带或灵敏度校准。

RTL 采样率合法区间来自 librtlsdr API：225001–300000 与 900001–3200000 S/s。推荐 AIO2 使用完整的 2.56 MS/s；2.048、2.4、2.56、2.8、3.2 MS/s 等档位可选择，超过 2.56 MS/s 显示连续性风险。USB 样本没有硬件序号，普通采集不能给出精确的硬件丢样数；`rtl_test` 的连续流短测另行记录。

来源参考：[librtlsdr API](https://github.com/osmocom/rtl-sdr/blob/master/include/rtl-sdr.h)、[调谐器概览](https://osmocom.org/projects/rtl-sdr/wiki/Rtl-sdr)、[RSPdx-R2 规格](https://sdrplay.com/wp-content/uploads/2026/06/RSPdxR2_Datasheet.pdf)、[SoapySDRPlay3 设置实现](https://github.com/pothosware/SoapySDRPlay3/blob/master/Settings.cpp)。规格范围不代表经过射频通带实测。

## 配置计划与联动

配置计划分别返回 `hardware_valid`、整体 `valid` 和带作用域的 `issues`。硬件约束包括采样率、输入模式、调谐范围、天线频率、IF 档位和手动增益；自动增益及直采模式下，无效的调谐器手动增益不参与校验。搜索宽度允许达到采样率所代表的整个复数采样频谱，超出采样范围仍拒绝；LoRa 的符号整数时序由内部采样率转换满足。完整信号仍需容纳在采样边缘以内，这一覆盖差异单独提示。

IF 可自动或手动选择驱动报告的档位。自动选择遵循 SoapySDRPlay3 的采样率兼容策略：不超过采样率的最大档位，例如 2/3 MS/s 配合 1.536 MHz IF、10 MS/s 配合 8 MHz IF；采样率低于最小 IF 时使用最小档位。允许高级用户手动选择已报告的更宽 IF，并单独提示带外混叠风险。IF 的 3 dB 带宽不再充当采样频谱的硬截断边界，边缘滚降和灵敏度下降单独说明。应用时回读确认；RTL-SDR 未提供滤波回读时显示未知。数据量按实际 I/Q 格式计算，CS16 每对 I/Q 占 4 字节，与 ADC 标称位数分开。

监听、录音扫描、回放与 FM 音频取消全局 3.2 MS/s 限制。RSP 可在 10 MS/s 下采集、显示和分析整个请求频谱。LoRa 和高采样率窄带分析采用重叠分信道，PSK/4-FSK 快照采用抗混叠的抽取路径；OFDM/CSS 快照仍检查原始频谱。实际实时能力受计算机和检测器数量影响，状态中公开积压、跳过、丢弃和 CPU，不通过静默缩带或关闭检测器使状态看起来正常。

## 桌面与命令行

接收机设置采用自适应双区域布局，优先使用屏幕宽度：顶部为设备及整体状态，左侧为参数和修复操作，右侧为调制评估表；宽度不足 1000 像素时改为上下排列。左右区域可拖动调整，并各自支持滚动。技术详情默认折叠，字段冲突独立显示，正常参数信息不再随错误整体变色。

主窗口和设置窗口使用相同的搜索宽度控件，提供常用预设、当前最大可用及自定义整数 kHz。推荐宽度使用整个当前采样范围；固定值和自定义值超限时保留原值并显示数值原因，不自动截断。最大可用模式随采样率联动，向下取整到 1 kHz；模式与数值一起保存。正常列表包含 RSP 的 10 MS/s 和 AIO2 的全部公开常用档位，高级选项还允许输入整数 S/s；真正的硬件或分析冲突仍不得应用。

“使用推荐配置”调用无 Qt 的 `recommendMonitorConfiguration`，保留中心频率和检测器选择，按设备推荐档位选择完整采样及搜索范围：RSP 优先 10 MS/s、10 MHz；AIO2 优先 2.56 MS/s、2.56 MHz。采用自动增益、自动 IF 和自动输入，仅在必要时改用兼容天线。推荐结果必须通过与会话启动相同的完整预检；无可行组合时不生成推荐，也不改变调谐频率或关闭检测器绕过约束。推荐代表可用的设备能力，不代表已经保证所有检测器在任意负载下实时运行。

只有完整监测配置有效时才允许“应用”，应用入口也再次检查完整计划。点击后异步执行硬件配置，成功回读后才返回主窗口并保存选择；执行期间禁止编辑或取消。主窗口显示兼容摘要，完整原因位于提示与接收机设置中；会话状态与 CLI 结果保留请求和实际配置。RTL-SDR 的自动增益模式没有读取接口，明确标为驱动接受设置，避免将请求值冒充回读值。

## 调制评估

评估覆盖检测注册表中的十项：LoRa、2-FSK/GFSK、OOK、ASK、广播 FM、BPSK、QPSK、4-FSK、OFDM、CSS。设置窗口继承各检测器的实际启用状态，并随参数编辑更新兼容性、内置解析能力及影响说明。各行调用共享配置计划分别判断；完整会话仍需满足所有已启用检测器的要求。未启用检测器、广播 FM 在当前搜索频段没有覆盖，不等于接收机整体参数冲突。

表格用简短描述便于同时比较各项，选择行后可展开详情，完整说明也保留在提示中。检测结论以配置条件为限，不推算信号成功率、灵敏度或误报率，也不将候选识别标为协议解码。LoRa 当前确认前导码/SFD 并估计 BW/SF，不恢复同步字和载荷；FSK/ASK/OOK/PSK 等输出调制候选；FM 支持导频检测和音频解调；OFDM/CSS 识别各自结构，不解码载荷。

影响说明来自实际实现：广播 FM 检测器仅检查 65–110 MHz，完整的 200 kHz 信道需落入采样带；PSK/4-FSK 使用触发快照及约 38 kHz 信道滤波；CSS 需重复的、跨度至少 40 kHz 的扫频；OFDM 对完整接收数据进行快照分析，并不按搜索宽度裁剪。上述支持描述不等于对该调制所有波形或速率提供通用识别。

```sh
signalscope probe --receiver sdrplay
signalscope validate --receiver sdrplay --purpose monitor --rate 2048000 --bw all
signalscope validate --receiver sdrplay --purpose capture --rate 10000000
signalscope configure --receiver sdrplay --rate 6000000 --gain auto --antenna 'Antenna B'
signalscope capture --receiver sdrplay --rate 10000000 --seconds 1 --output capture-wide
signalscope validate --receiver rtlsdr --rate 2400000 --gain auto --lora 0
```

`validate` 输出能力、请求和配置计划；无效组合返回非零状态，仍保留结构化 JSON。`configure` 输出 `requested`、`actual` 及驱动回读来源。RSP 成功激活后额外返回 `activation_confirmed`，避免将初始化前的缓存参数当作已经通过启动验证的结果。设置窗口关闭设备后，开始监听时会重新配置。无效监听组合在创建会话目录前拒绝。

## 验证边界

原生回归覆盖调谐器差异、采样率空档、非推荐档位、天线频率边界、自动/手动增益、LoRa 时序和通带、ADC 与格式区分、能力序列化、模拟驱动的配置回读与拒绝配置，以及桌面编辑和应用链路。模拟测试验证软件契约，不替代 USB、实际射频和持续吞吐验收。

设置窗口测试默认使用替身驱动；系统已装厂商模块时跳过，避免普通回归修改实体设备。经授权的实机验收可显式设置 `AMC_TEST_REAL_SDRPLAY=1` 运行 `receiver_dialog_test`，该模式要求连接 RSPdx-R2，并实际应用 3 MS/s、天线 B 的配置和校验回读。`AMC_RECEIVER_DIALOG_SCREENSHOT` 可指定测试窗口截图路径。
