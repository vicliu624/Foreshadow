# 独立广播会话与状态栏

[English](21-independent-broadcast-sessions.md) · 简体中文

## 使用方式与兼容性

广播收听与宽带发现是并列入口。FM、DTMB 面板可以在未启动监听时调谐、收藏、命名并开始播放；检测事件可以交给所属提供者加入收藏。普通收听使用提供者声明的输入需求，由接收机插件给出合法推荐。保留完整接收参数、实际回读、模块高级设置及诊断，不删除宽带监听、研究与手动配置能力。

收藏属于模块用户数据，具备版本和稳定标识。FM 保存频点、用户名称；DTMB 保存射频复用频点与节目身份，不以易变的音视频 PID 作为节目身份。旧设置保留。临时播放配置不得覆盖用户保存的宽带配置。

## 边界与协议

| 变化轴 | 所有者 | 稳定消费者与组装 |
|---|---|---|
| 输入频带、最低采样率及解调选项 | 广播研究提供者 | 实时研究宿主只传递通用需求 |
| 硬件合法配置、联动、推荐、实际回读 | 接收机插件 | 接收会话按通用需求筛选插件推荐 |
| 设备使用权、共享、释放、冲突 | 通用接收会话 | 监听及研究工具持有独立租约 |
| 收藏、搜台、节目选择、播放控制 | FM／DTMB 提供者 | 工作区与菜单不识别模块 ID |
| 运行摘要与导航 | 通用状态描述及桌面宿主 | 底部状态栏只渲染描述并执行动作 |

实时研究生命周期显式升级为 v2，新增按需申请接收机及释放租约的协议；v1 工具继续使用原有监听上下文。独立工具不能直接打开厂商驱动。跨线程回调须隔离异常、失效代次及已销毁对象。采集回调不得执行界面、等待解调或声卡。

输入需求与租约协议属于 `backend/iq/reception.hpp`，不依赖会话实现或界面；物理使用权由 `ReceiverSession` 实现。接收机选择导航通过可选宿主回调注入模块，模块不得导入接收机对话框。新协议能力不得冒用旧版本，v1 不声明 v2 接收、摘要或导航能力。

### 启动校准与过载事实

`ReceiverReadback` / Ready JSON v2 与 `ReceptionStatus` v2 增加 `AcquisitionConditions` v1，所有者为 `backend/iq` 的数据协议，设备事实由接收机提供者产生。Ready 仍只在首个样本前调用一次；原有 C ABI 1 函数表不变，未声明 Ready 版本的旧插件继续按 v1 读取，新增事实全部为未知。已声明但不支持的版本或自相矛盾的事实必须拒绝，不能退回为兼容成功。此升级没有动态遥测能力。

事实头使用 `org.amc.acquisition-conditions` / version 1，scope 固定为 `before_first_samples`，origin 区分 `provider` 和 `not_reported`。频率与幅度校准分别声明 unknown / uncalibrated / calibrated / not_applicable，已校准及不适用必须保留提供者证据。ADC 监测能力 unknown / unavailable / available / not_applicable 与启动观测 unknown / detected / not_detected / not_applicable 分开；检测结论只能来自可用监测且有证据，不可用不能报告未检测到。未知字段保留，单份事实最多 64 KiB。

时钟校正参数、实际增益回读、数字样本幅度、USB 溢出或软件队列丢弃都不能替代校准证据或 ADC 过载传感器。当前 RTL-SDR 和 SDRplay 提供者没有导出 ADC 观测，明确报告提供者未提供监测、过载未知；这不表示物理硬件永远不具备该能力。当前协议也没有覆盖冻结窗口期间的 ADC 观测，界面必须继续显示窗口过载未知，即使启动时报告未检测到。需要实时或区间观测时须另行升级协议、采样覆盖与消费者能力，禁止重复调用 Ready 伪装为遥测。

接收会话按采集代次传递启动事实，兼容共享的新租约收到同一份事实；换源后不得沿用上一次报告。波形捕获将事实连同请求、实际回读及未知诊断保留在冻结窗口接收上下文，保存后回读验证。报告已校准也不能单独改变 dBFS 的含义；dBm 转换仍需要独立的有效幅度标定与适用范围。

## 设备协调

现有流满足完整频带与采样约束时共享一次采集；监听的精确配置需求与播放的最低需求分别表达。实际回读必须再次校验。单调谐器无法满足的并发请求明确报冲突，保留正在运行的任务；切换需用户明确操作。不得静默中断录制。停止监听只释放监听租约，仍在使用接收机的广播继续接收；仅剩播放时允许重选较小合法配置，并显示重新配置／缓冲状态，不保证重调无间隙。停止播放释放自身租约；隐藏窗口不停止播放。显式断开设备与退出应用释放所有使用者。

只有最低需求消费者运行时，兼容的宽带监听可以升级输入配置；新的配置必须满足全部现存需求。已有精确配置使用者固定配置，不能在其运行时重调。释放使用者后，经济配置按剩余消费者的完整占用频带联合求值，不能只满足列表中的第一个消费者。

自动模式使用接收机插件的推荐；手动模式在所选广播频点使用当前接收机手动参数，并执行整套硬件校验。两种模式都保留请求与实际回读，临时调谐不覆盖宽带偏好。硬件占用检查针对实际设备身份，不能因为序号／序列号别名而重复打开，也不能禁止用户选择另一台空闲设备。

UI 应用当前代次输入配置后，宿主才向该代次解调器放行 I/Q；等待配置期间跳过的样本单独统计为 `configuration_wait_pairs_total`。租约释放不等待已进入的非阻塞回调，提供者必须以独立的共享工作状态保留管线生命周期，不得让采集回调依赖已销毁的组件。

## 底部状态栏

状态栏持续展示接收机、当前任务、主机负载和需要处理的告警；可以点击进入对应详细面板。窄窗口优先保留当前任务与故障，其余用提示展示。状态与健康面板保留完整指标。驱动／输入连续性、各分析阶段丢弃、音频欠载分别计量；历史累计不冒充当前故障。更新通知不能覆盖持久运行摘要。文案及缺失翻译回退遵循资源协议。

共享输入仍在运行时，已经停止的监听任务不得伪造最终驱动统计；报告应标明未完成及对应采集代次。驱动异常的结构化证据原样保留，监听输入队列拒绝属于软件消费者，不能冒充硬件丢样。显式断开全部接收机不停止与硬件无关的文件播放或回放。

## 验收

使用独立接收机提供者和独立研究提供者验证主体不增加 ID 分支。验证单独收听、共享、冲突、停止监听继续播放、最后租约释放、实际回读不满足需求、异常隔离、快速启停与持续输入的字节预算。验证收藏跨启动、命名、删除、事件收藏、搜台取消和 DTMB 同复用切台。保留原有参数校验、监听、录制、回放和工作区布局回归。发布报告区分合成输入、实体硬件与外部阻断；uConsole 不连接天线时只验编译、启动和模块加载。
