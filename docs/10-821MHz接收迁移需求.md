# 821 MHz 接收迁移需求

[English](10-821mhz-reception-migration.md) · 简体中文

更新日期：2026-11-04。本文记录用户最新范围调整，优先于此前文档关于“当前工作目标为 478–479 MHz LoRa”的安排。需求确认不代表功能已经实现或部署。

## 工作目标

将 uConsole + AIO2 的工作监听窗口迁至 821 MHz 附近，以 821.2375 MHz 为 LBJ 接收研究目标。不安排 478 MHz 与 821 MHz 之间的轮扫，也不要求两段同时接收。保留此前 LoRa 检测、录制与重放能力和历史数据，但不把 478 MHz 监听作为本次迁移的并行任务。

## 接收与识别

现有 Dechirp + FFT 用于 LoRa 结构检测，不能用来确认 LBJ。迁移应同时增加独立的接收模式，包含信道提取、FSK 鉴频、比特同步、POCSAG 帧同步和 BCH／奇偶校验。1200 bit/s 作为待验证的初始候选，须用独立测试数据及实际录制确认。

公开接收项目 [CR_LBJ_Receiver](https://github.com/liujitong/CR_LBJ_Receiver) 记载了 821.2375 MHz 接收、960 kS/s 输入抽取至 48 kS/s 基带、FM 鉴频及 BCH(31,21) 解码链路。这提供实现参考，不证明本机已接收到该系统，也不能据此推断本地覆盖情况。

采集中心频率、目标信道频率、采样跨度和实际检测信道宽度应在界面分别显示。采样率与信道滤波宽度通过实测确定，不能把整段采样跨度称为 LBJ 信号带宽。

## 证据与界面

事件分级显示，避免用强载波或单次相似特征代替协议确认：

1. **射频活动**：目标附近存在能量或突发，仅说明接收到信号。
2. **POCSAG 候选**：出现相应同步特征，但校验或连续结构不足。
3. **POCSAG 校验通过**：报告有效码字数量、BCH 与奇偶校验结果、是否纠错及原始码字；仍不自动确定为 LBJ。
4. **LBJ 报文解析通过**：只有在应用层字段、长度和报文规则得到验证后，才展示对应车次、速度、公里标等字段；未支持或未确认的字段留空。

界面保留实时频谱、瀑布、数字域信号强度、事件时间、证据详情、录制与离线重放。未经射频标定的强度使用 dBFS，不标作绝对 dBm。不得继续将该模式的事件标作 LoRa、SF 或 Chirp。

## 存储与迁移

继续使用有界内存预录和磁盘配额，不连续保存全天原始 I/Q。默认只自动保留达到协议验证门槛的事件；普通能量活动和未验证候选仅保留有界摘要。人工研究录制应有明确时间及大小上限。

迁移时结束原 478 MHz 会话，并记录旧长稳观察因任务变更而中断；不拼接为同一次连续验收。历史录制保留，821 MHz 事件使用独立目录或明确模式元数据。接收研究不需要射频发射。

## 验收及当前状态

先验证离线 FSK／POCSAG 样本的同步与校验、反极性、频偏、噪声反例，再验证 AIO2 实际调谐、连续采样、界面和有界存储。实际环境未出现校验通过的报文时，应报告“尚未捕获有效报文”，不得把合成数据或普通载波计作环境 LBJ。

2026-11-04 检查：目标机仍运行中心 478.5 MHz、1.75 MS/s 的 LoRa 检测版本。本文仅完成迁移需求确认；821 MHz 接收模式、POCSAG 检测与实际部署尚未完成。
