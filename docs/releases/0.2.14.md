# Foreshadow 0.2.14

English · [简体中文](0.2.14.zh-CN.md)

This maintenance release includes [PR #2](https://github.com/vicliu624/Foreshadow/pull/2), merged into `main` at `7ab14d9`. The release selection is Windows x64, Debian 13 x64 and Debian 13 ARM64 / uConsole. macOS is outside this release selection. Publication requires the frozen-source native builds, extracted-package checks, corresponding-source validation and locally signed catalog described below; preparation alone is not publication.

## Changes

- New SigMF recordings identify Foreshadow and the actual build version. Existing metadata remains readable and full export preserves source bytes.
- Managed Linux updates preserve existing custom desktop launch options when the entry has a valid bootstrap for the same installation.
- Cold GUI and CLI launches retain their selected toolbox store through an optional absolute UTF-8 `distribution_root`. Legacy launcher configurations remain supported.
- Toolbox actions follow the selected package row, including accessibility selection without a keyboard-current cell.
- Physical waveform acceptance recognizes the explicit receiver-reconfiguration transition without relaxing other error, budget or frozen-observation identity checks.

The [RSPdx-R2 workflow report](../reports/2026-11-24-rspdx-r2-workflow-review.md) records real capture, recording, replay, waveform research and signed toolbox lifecycle evidence that led to these fixes. Its local review source and counters are historical evidence, separate from this release's final artifacts and qualification record.

## Publication checks

The existing formal workflow builds all three selected platforms with matching source and reviewed dependency inventories. It verifies base and independent toolbox transactions, native GUI/media/receiver workflows, independent AVS+/DRA references and extraction into Chinese/non-BMP paths. Audio-device skips and platform timing limits must be reported as such.

All application and independent receiver/research packages include matching corresponding source, dependency source, notices and replacement instructions. The publisher validates their actual archive contents against the repository-reviewed profiles before signing. The established public trust key and catalog URL remain unchanged; signing keys stay outside the repository, CI and deployment hosts.

After publication, the receiver workstation must discover 0.2.14 through **Plugins → Toolbox Center → Check for updates**, install through the normal signed-catalog transaction, restart/activate successfully and retain its independent SDRplay client, receiver settings, recordings and accepted Windows forwarding route. This is a required post-publication check, not an already completed claim in this frozen source note.

## Compatibility and scope

Package IDs, settings roots, CLI names and file formats remain compatibility protocols. Full FM, waveform, ADS-B, DTMB and television/media functionality is retained. SDRplay Support is an independent network client; the vendor API/service and firmware are not bundled. GPL-3.0-or-later, the existing codec assessment and provider notices continue to apply.

The earlier hardware report records a client timeout and an initial short waveform capture with rejected input pairs, separately from zero main-analysis discarded pairs and the later dedicated lease test. Neither that report nor software/package checks establish uninterrupted hardware sampling, calibrated RF power, physical audio output or successful decoding of unknown over-the-air signals. Updates on `.42` use the explicitly accepted Windows forwarding connection, which must remain online.
