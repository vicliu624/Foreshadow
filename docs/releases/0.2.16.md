# Foreshadow 0.2.16

English · [简体中文](0.2.16.zh-CN.md)

This patch fixes resource lifetime defects found while investigating an overnight
`Too many open files` report on the receiver workstation. The
[native audit](../reports/2026-11-25-resource-lifetime.md) records the reproduced
defects, before/after descriptor counts and limits of incident attribution.

## Corrections

- The SDRplay remote client's logging recovery now joins the previous thread and
  closes its socket before reconnecting. Unsubscribe does not open a replacement
  connection; thread completion uses an atomic flag.
- A rejected remote device creation releases its log subscription during
  constructor unwinding. Ownership transfers only after construction succeeds.
- Recording-directory lock descriptors are not inherited by child executables:
  POSIX uses `O_CLOEXEC`, Windows uses `_O_NOINHERIT`.

The changes stay in the recording backend and receiver-client assembly. Existing
session, GUI, installer, package IDs, command names and settings remain compatible.
Full ADS-B, WSPR, waveform/PSK/OFDM, television and optional toolbox functionality
is retained. The original independent receiver service and vendor API are not
bundled or changed by this patch.

## Validation and release scope

New tests count native process resources across rejected/successful construction,
repeated log disconnect/recovery, recording/replay completion and cancellation,
and provider stream success/failure. They reuse the client process so process exit
cannot hide retained resources. The independent upstream service and a TCP fault
relay exercise the real client; recording tests cover both CU8 and CI16 fixtures.
Windows checks inspect the actual lock handle's inheritance flag as well as child
behavior. Child readiness waits for a complete line with a deadline and accepts
native line endings rather than treating the first process notification as ready.

**[0.2.16 is published](https://github.com/vicliu624/Foreshadow/releases/tag/v0.2.16)** for Windows x64, Debian 13 x64 and Debian 13 ARM64 / uConsole, from `d33e438c0c2ca8c693dd4905c6ce2392aec5bcd8`. The formal suites passed 129 Windows and 130 tests on each Linux architecture, with two unavailable-audio skips per platform and no failures. Actual archives, package transactions, Unicode/non-BMP paths, native runtime checks and material validation passed. The [qualification record](https://github.com/vicliu624/Foreshadow/releases/download/v0.2.16/release-qualification.json) contains exact identities and evidence; the [release/update report](../reports/2026-11-25-0.2.16-release-and-update.md) records native deployment status. macOS remains outside this release. Bounded software/hardware observations do not prove overnight stability or indefinite losslessness.

## Updating

Use **Plugins → Toolbox Center → Check for updates**, install the application and
the relevant receiver/research toolboxes, then restart. **Update SDRplay Support
as well as the application**: the remote logging fixes are in that independent
client package. Settings, recordings and saved analysis are preserved. The
workstation's accepted Windows forwarding connection must remain online for its
current network route.

The upstream source archive and BSL-1.0 notices are preserved. Local client
changes, build recipes, bilingual explanations and hashes accompany each
applicable package; source preparation uses private build-tree copies and fails
if a pinned patch context changes. Main application/first-party plugins remain
GPL-3.0-or-later. Release signing stays on the publisher computer, outside the
repository and build/deployment hosts.
