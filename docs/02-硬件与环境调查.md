# 硬件与环境调查

[English](02-hardware-and-environment.md) · 简体中文

## 本版补充：LoRa 连续宽带采集验证

2026-11-03 范围更新：本版仅验证 uConsole+AIO2 的 LoRa 短突发检测，不调查 LR2021 作为实现前置条件。下文通用设备调查仍适用，报告另须包含：

- 2.0/2.4 MS/s 下采集、显示、检测和写盘联合负载；原始跨度不直接称为有效通带。
- 在 470–510 MHz 候选区的天线、频率误差、滤波边缘、直流附近及强信号条件；逐位置验证初始 1 MHz 中心搜索范围。
- 完整信号覆盖宽度：中心搜索宽度 + 最大目标 LoRa 带宽 + 两侧保护余量。中心范围 1 MHz、目标 BW125/250/500 kHz 时，未计保护带的需求分别为 1.125/1.25/1.5 MHz。
- 检查偏置调谐或直流处理效果，不以屏蔽中心频点冒充连续覆盖。
- 用户自有 LoRa 设备的实际频率、BW、SF、前导码、发送节奏和停止发射状态，用于独立实测记录；配置真值不直接输入未知频点检测器。
- 环形缓冲容量按样本格式和秒数估算，并覆盖检测确认耗时与积压；记录磁盘配额和外部存储可用性。

以上均待验证，不预先填写实测结论。

## 1. 调查状态

目标设备：ClockworkPi uConsole、Raspberry Pi CM4、HackerGadgets AIO V2。2026-11-03 已连接 vicliu@192.168.50.92，实测 Debian 13.7 / aarch64 / CM4，USB 识别 AIO_V2 Ext；2.0 与 2.4 MS/s 均完成短时采集和重放。见[首次报告](reports/2026-11-03-首次采集与环境记录.md)。全频段、HF、有效通带、调谐稳定时间和长期无漏样尚未验证，不能由短时成功推导全部能力。

## 2. 调查步骤

先记录原始环境，再进行采集测试。以下命令在目标 Linux 上按可用情况执行；缺少工具时记录缺失项，安装依赖前先检查发行版及软件源。命令输出可能含设备序列号，对外分享时按需脱敏。

```bash
date -u
uname -a
cat /etc/os-release
getconf LONG_BIT
lscpu
free -h
df -h
lsusb
lsusb -t
lsmod
command -v rtl_test
command -v rtl_sdr
command -v cmake
command -v c++
command -v pkg-config
cmake --version
c++ --version
pkg-config --modversion librtlsdr
```

检查近期内核日志中的 USB 枚举、复位、断连和 DVB 驱动占用。`dmesg` 可能需要额外读取权限；无权限时记录限制。不要未经确认直接卸载内核模块或修改系统黑名单。

运行本机工具的帮助信息，确认该构建支持的参数后，再执行设备枚举和采样测试：

```bash
rtl_test -h
rtl_sdr -h
```

若本机构建支持对应参数，可分别测试 2.0 MS/s、2.4 MS/s；每次只运行一个采集进程，记录持续时间和工具报告的错误，使用 Ctrl+C 正常结束：

```bash
rtl_test -s 2000000
rtl_test -s 2400000
```

这两档只是需求提出的初始候选，不代表已证明稳定。应测试固定频点采样、反复调谐和启用显示/写盘后的综合负载。工具未报告错误也不必然证明没有任何未知丢样。

## 3. 必须确认的能力

| 项目 | 方法与记录要求 |
|---|---|
| USB 设备 | VID/PID、枚举名称、驱动实际识别型号、连接拓扑、序列号可用性 |
| 驱动 | librtlsdr 来源、版本或提交、是否厂商分支、设备占用情况 |
| 频率范围 | 驱动返回能力、实际调谐成功范围、已验证接收点分别记录 |
| HF 模式 | 实际硬件路径、模式切换方法、所需驱动、可用频段；未验证则标记不支持或未知 |
| 采样 | 请求与实际采样率、8 位输出编码、字节顺序、块大小、稳定性 |
| 增益 | 支持的离散档位、自动增益行为、切换稳定时间 |
| 调谐 | 请求到有效样本的耗时、应丢弃样本量、不同频段差异 |
| 有效带宽 | 滤波边缘、中心直流影响、保护带与窗口重叠建议 |
| 频率误差 | PPM 设置支持及可测参考，不以未经校准频点当作标准 |
| 系统资源 | 空闲与负载下 CPU、RAM、温度/降频信息、可用存储及写速 |
| 界面 | 实际分辨率、缩放、显示服务、Qt 可用性、输入方式 |

频段边界和 HF 支持不能仅由 R860 型号推导。若无已知参考信号或测试源，只能证明调谐请求接受，不能证明对应频段接收性能。

## 4. 采样与容量估算

若采集数据为每个复样本两个 8 位分量，2.0 MS/s 原始数据约 4.0 MB/s，2.4 MS/s 约 4.8 MB/s；连续一小时分别约 14.4 GB 和 17.28 GB，均为十进制估算，不含元数据和文件系统开销。

若内部转为每个复样本两个 32 位浮点数，数据流约为 16.0 MB/s 和 19.2 MB/s。环形缓冲内存按“采样率 × 每复样本字节数 × 缓冲秒数”计算。调查时据此确定预触发时长、录制上限、磁盘余量和复制预算。

## 5. 报告模板

实际执行后创建 `docs/reports/硬件能力报告.md`，填写：

- 调查日期、操作者、硬件版本、系统与内核、架构。
- 工具链、驱动和依赖的精确版本及来源。
- 调查命令、完整日志位置和无法执行的原因。
- 驱动声明能力、实测能力及尚未验证能力。
- 采样率与负载组合、测试时长、错误计数、连续性限制。
- 调谐稳定时间、保护带、频率误差与推荐首轮配置。
- CPU、内存、温度、存储、显示条件。
- 限制、可验证替代方案及是否满足进入实时开发阶段的条件。

若设备暂不可用，可推进文件源、合成数据、检测与离线 AMC；硬件验收保持未通过状态。
